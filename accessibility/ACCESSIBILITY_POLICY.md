# Accessibility Policy

## Purpose

ORCHORDS aims to make public digital content usable by people with diverse abilities, devices, and assistive technologies.

## Standard

Public web content and documentation SHOULD conform to WCAG 2.2 Level AA where applicable. Conformance claims must be based on evidence; this policy does not itself assert conformance.

## Requirements

- Keyboard access must not depend on a pointing device.
- Focus order and visible focus must support task completion.
- Text and interactive controls must have sufficient contrast.
- Forms must provide programmatically associated labels and useful errors.
- Meaningful images need appropriate text alternatives.
- Meaningful prerecorded audiovisual content should provide captions or equivalent alternatives.
- Motion and animation should respect user preferences and avoid unnecessary seizure or vestibular risk.
- Headings, landmarks, names, roles, and states should be semantically useful.
- Documentation uses descriptive links, simple tables, and logical heading order.

## Verification

Accessibility review combines automated checks, keyboard-only testing, targeted assistive-technology testing, manual review, and regression review after material changes. Automated tools are evidence, not proof of conformance.

## Defects

Accessibility defects are prioritized by user impact, frequency, and availability of a workaround.
