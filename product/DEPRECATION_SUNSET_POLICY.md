# Deprecation and Sunset Policy

## Purpose

Manage retirement of capabilities, interfaces, integrations, and supported versions without creating unnecessary user, security, or data risk.

## Requirements

Material deprecation SHOULD define owner, reason, affected users or dependencies, notice approach, migration or export path where appropriate, support end date or event, security implications, data handling, and final removal criteria.

## Security

Unsafe or unsupported capabilities may require accelerated retirement. User convenience must not preserve a known critical security condition indefinitely.

## Communication

Avoid indefinite ambiguous "deprecated" states. Explain what changes, what users should do, and when the old path will stop being supported when that information can be responsibly published.
