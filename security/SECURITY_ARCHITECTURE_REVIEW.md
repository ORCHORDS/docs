# Security Architecture Review

## Purpose

Apply focused security review before material designs create hard-to-reverse exposure.

## Triggers

Review is appropriate for material changes in trust boundaries, identity/privilege, sensitive data, external exposure, cryptography, third-party dependency, AI tool permissions, administrative capability, or recovery architecture.

## Output

A review SHOULD record scope, assumptions, material threats, required safeguards, residual risks, owners, and conditions for re-review. It should avoid publishing private topology or exploitable implementation detail.

See [Security Architecture Review SOP](../sop/SECURITY_ARCHITECTURE_REVIEW_SOP.md).
