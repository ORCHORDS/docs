# Security Metrics and Reporting

## Purpose

Use security metrics to support decisions without creating false assurance or incentives to optimize the number instead of the underlying control.

## Requirements

Security reporting SHOULD combine leading and lagging indicators, state scope and data limitations, identify the accountable owner, preserve trend context, and distinguish target performance from observed evidence.

Useful measures may include remediation age, exception age, privileged-access review completion, control-test results, incident recurrence, detection/response timing, unresolved high-risk findings, and supplier-security issues.

## Integrity

Metrics must not hide materially overdue items through averaging, exclude failed controls without explanation, or present a percentage as proof that risk is acceptable.

## Review

Material metrics are reviewed for usefulness, gaming risk, data quality, and whether thresholds still support current risk decisions.
