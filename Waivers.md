## Purpose

This document defines the process for requesting, approving, and tracking security waivers for Beetle Studio. A security waiver is a formal exception to a security policy or standard, granted when compliance is not feasible within project constraints.

---

## Waiver Request Process

1. **Identify the requirement** that cannot be met
2. **Document the risk** using the template below
3. **Submit** to the Security Review Board (Kirk Beka, Maya Rodriguez)
4. **Review** within 5 business days
5. **Decision** recorded in the Waiver Registry

---

## Required Fields

| Field | Description |
|---|---|
| **Waiver ID** | Unique identifier (WAV-YYYY-NNN) |
| **Requestor** | Name and role of the person requesting |
| **Policy Reference** | The specific policy or standard being waived |
| **Risk Description** | Detailed description of the security risk introduced |
| **Justification** | Why compliance is not feasible |
| **Compensating Controls** | Alternative measures to mitigate the risk |
| **Expiry Date** | When the waiver expires and must be re-evaluated |
| **Approver** | Name and role of the approving authority |
| **Approval Date** | Date the waiver was granted |

## Review Schedule

- **Monthly:** Review all active waivers for continued validity
- **Quarterly:** Full audit of waiver registry by CTO
- **On expiry:** Waiver must be renewed or the requirement must be met
- **On incident:** Any security incident triggers review of related waivers

## Escalation

Waivers for critical or high-risk items require CEO approval in addition to the Security Review Board.
