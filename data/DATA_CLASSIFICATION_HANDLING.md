# Data Classification and Handling

## Purpose

Provide a simple company-wide model for handling information according to
sensitivity and plausible harm.

## Classification model

| Class | Typical meaning | Handling expectation |
|---|---|---|
| Public | Approved for public distribution | Integrity and publication review |
| Internal | Routine non-public company information | Authenticated access and normal business safeguards |
| Confidential | Information whose exposure could materially harm people or ORCHORDS | Need-to-know access, controlled sharing and appropriate encryption |
| Restricted | Highest-sensitivity information such as secrets or specially protected data | Strong access control, minimized copies, enhanced monitoring and explicit handling rules |

Classification is based on content and impact, not file location.

## Handling rules

- Apply the most protective classification required by the information present.
- Do not place non-public information in public repositories.
- Share only with authorized recipients for a legitimate purpose.
- Use approved transfer and storage methods appropriate to sensitivity.
- Limit copies and retention.
- Reassess classification when data is combined, transformed, published, or
  de-identified.

## Public documentation

Examples in this repository use fictitious values and must never include real
credentials, customer data, restricted identifiers, or private operational
detail.
