# Problem Management

## Purpose

Reduce recurrence by managing underlying causes, not only individual incident
symptoms.

## Triggers

Problem analysis SHOULD be considered for:

- repeated incidents;
- high-impact incidents;
- recurring control failures;
- unexplained performance degradation;
- repeated manual recovery;
- clusters of similar defects or user reports.

## Method

A problem record should capture observed patterns, known impacts, hypotheses,
evidence, contributing factors, workarounds, permanent actions, owners, and
verification of effectiveness.

## Root cause

Avoid forcing a single "root cause" when several technical, process, and human
factors contributed. The goal is durable improvement, not blame.

## Closure

A problem is not closed merely because the latest incident ended. Closure
requires either verified corrective action, accepted residual risk, or a clear
reason no further action is justified.
