# GitHub Copilot Copyright Commitment (IP Indemnification)

## Overview
The Copilot Copyright Commitment is GitHub's IP-infringement indemnification
promise for eligible Copilot offerings. In 2026 coverage extends across
Copilot Business and Copilot Enterprise (and the equivalent Enterprise Managed
User surfaces). In plain terms: if a third party sues an eligible customer for
copyright infringement based on code generated by Copilot, GitHub will step in
to defend the customer and pay certain damages, subject to the commitment's
conditions.

This is the legal counterpart to the technical "duplicate detection filter"
(`github-copilot-duplicate-detection-filter.md`): the filter reduces the risk
that suggestion output matches public code; the Copyright Commitment limits
the customer's financial exposure for whatever risk remains.

## Symptom
- Legal counsel asks "what is our IP exposure if an engineer ships Copilot-
  generated code that turns out to infringe?" and engineering has no answer
  because nobody knew the commitment existed.
- A team wants to disable Copilot for a high-risk repo (closed-source
  commercial product) over IP fears, when the actual mitigation is to confirm
  they are on an eligible plan and enable the duplicate-detection filter.
- Procurement is comparing Copilot Enterprise vs an uncapped competitor and
  needs the indemnification terms spelled out.
- An engineer pasted a Copilot suggestion into a customer deliverable and the
  customer is now asking for IP indemnity.

## Gotchas
- **Plan eligibility is strict.** The commitment only applies to Copilot
  Business and Copilot Enterprise, not to Copilot Individual (Free / Pro
  consumer) subscriptions. If an engineer upgraded with a personal account and
  uses it for work, the company is not covered for that usage.
- **Duplicate-detection filter must be ON.** The commitment conditions on the
  customer having the public-code duplicate-detection filter enabled (where
  available) and not having bypassed it. A team that disabled the filter
  because it "rejected too many suggestions" has quietly voided their coverage
  for those suggestions.
- **The commitment covers copyright, not patents or other IP.** Do not read it
  as a blanket "AI output is risk-free". Trademark, trade-secret, and patent
  claims are out of scope.
- **Output must be generated in the eligible product.** Code the engineer got
  from a non-Copilot LLM and then edited in a Copilot-enabled IDE is not
  "Copilot output" for this purpose. Be honest about provenance during any
  claim.
- **Prompting matters.** The commitment can be carved out where the customer
  deliberately prompted Copilot to reproduce a specific copyrighted work
  ("give me the source of X"). It protects against inadvertent matches, not
  intentional copying.
- **Notice and control.** The customer must notify GitHub promptly and let
  GitHub control the defense. Settling unilaterally can void coverage.
- **EMUs and GHE.** For Enterprise Managed Users (`github-enterprise-managed-
  users.md`) and GitHub Enterprise Server, confirm the commitment attaches to
  your specific entitlement; the wording can differ slightly from .com.

## Eligibility Checklist
- [ ] Organization is on Copilot Business or Copilot Enterprise.
- [ ] Every engineer using Copilot for company work is on a seat owned by that
      org (not a personal Individual subscription).
- [ ] Duplicate-detection filter is enabled at the org/policy level and not
      user-disabled.
- [ ] Engineers have been trained not to prompt Copilot to reproduce specific
      third-party code.
- [ ] You have a record of which repos/surfaces are in scope (IDE, CLI,
      coding agent) so a claim can be scoped quickly.

## Operationalizing It
1. **Inventory seats.** Export the Copilot seat list and reconcile with HR.
   Disable personal-subscription usage for company work.
2. **Lock the filter.** Use the Copilot policy settings to enforce duplicate
   detection org-wide; document the setting with a screenshot and date for the
   claim file.
3. **Update your SaaS risk register.** Add Copilot output as a category with
   "mitigation: Copyright Commitment + duplicate detection; residual risk:
   low/medium".
4. **Brief engineers.** One-pager: "Copilot output is indemnified for
   copyright on Enterprise, *if* you leave the duplicate filter on and do not
   ask it to copy specific code. Report any takedown notice to Legal
   immediately."
5. **Customer-facing stance.** If customers ask for IP indemnity on deliverables
   that include Copilot output, your legal team can layer your own indemnity
   on top of GitHub's, but only up to what GitHub covers — do not promise more.

## How It Relates to Adjacent Features
- **Duplicate detection filter** (`github-copilot-duplicate-detection-filter.md`)
  is the technical precondition. Read them as a pair.
- **Copilot privacy/retention settings** govern prompt-content handling and
  are independent of the Copyright Commitment. Do not conflate "we are in
  privacy mode" with "we are indemnified".
- **Copilot coding agent** (`github-copilot-coding-agent.md`) output is in
  scope where the agent runs on an eligible plan; verify autonomous output is
  covered before letting the agent commit to customer-facing repos.

## Summary
The Copyright Commitment converts an open-ended IP risk into a bounded one,
but only if you meet the conditions: right plan, filter on, no deliberate
copying, prompt notice. Treat eligibility as a configuration to maintain, not
a one-time checkbox — a single engineer on the wrong plan is an uncovered gap.
