# product-update-digest

**Issue:** Designing a product update digest email for regular feature announcements
**Date:** 2026-08-11
**Status:** documented

## Symptom / Context
Users don't notice new features unless proactively told; a digest email drives feature adoption and retention.

## Pattern / Solution
Structure:
1. Hero: Most important new feature with screenshot and CTA.
2. Secondary: 2-3 smaller improvements as bullet list.
3. Tip: One usage tip for an existing feature.
4. Footer: Link to full changelog, feedback link.

Cadence: Monthly for most SaaS; weekly for fast-moving dev tools.

Content rules:
- Lead with user benefit, not feature name: "Now you can export reports in one click" not "New export feature".
- Include screenshot or GIF for visual features.
- Deep-link CTA to the exact feature in-app.

Segmentation: Plan-appropriate features only (don't announce paid features to free users without upgrade CTA).

## Gotchas
- Changelog email open rates decline over time; keep content high-signal, not exhaustive.
- Users on digest skip irrelevant updates; keep it scannable with clear headers.
- Do not over-promise; vague "improvements" lose credibility.
