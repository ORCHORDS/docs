# User Feedback Handling

## Purpose

Turn user feedback into evidence for product and risk decisions without treating every request as equal priority.

## Intake

Feedback SHOULD capture enough context to understand user goal, affected workflow, frequency, impact, workaround, and supporting evidence when available.

Security-sensitive reports must be redirected to the private security-reporting process rather than discussed publicly.

## Analysis

Look for patterns across support requests, usability issues, incidents, accessibility barriers, cancellations, and direct research. A loud single request is not automatically representative.

## Privacy

Feedback records must minimize unnecessary personal data and follow retention requirements.

## Closure

Where practical, important feedback should be linked to a decision, experiment, issue, or explicit reason not to act.
