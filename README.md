# ORCHORDS Public Documentation

**Independent software studio founded in 2025.**

Public company-wide documentation for ORCHORDS governance, security, privacy, data, AI, engineering, operations, resilience, people, compliance, customer trust, legal, finance, communications, product, research, accessibility, standards, releases, and related business controls.

## Public-repository boundary

This repository is intentionally **not** a system inventory or private architecture repository. Do not publish credentials, secrets, private endpoints, customer information, internal identifiers, non-public infrastructure details, banking/tax records, active transaction details, unreleased work, or other sensitive information.

## Documentation principles

- Prefer current primary or authoritative sources for factual claims.
- Check existing related documents before creating new content.
- Avoid duplicate or near-duplicate pages.
- Distinguish policy requirements from implemented controls.
- Do not imply certification, deployment state, control effectiveness, or operational capability without current evidence.
- Keep category indexes and count-bearing documentation synchronized with repository contents.

## Workflow

Authorized routine documentation maintenance is performed directly on **`main`**. Feature branches and pull requests are not required for routine documentation growth or maintenance.

Changes must remain narrowly scoped, source-verified, duplicate-checked, and reviewed for public-safety boundaries before commit.

See [CONTRIBUTING.md](./CONTRIBUTING.md).

## Security

Do not report security-sensitive findings in a public issue. Follow [SECURITY.md](./SECURITY.md).
