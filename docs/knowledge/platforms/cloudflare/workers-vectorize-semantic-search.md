# Semantic Search with Cloudflare Vectorize

Date: 2026-08-24
Author: example.com
Status: production

---

## Symptom / Use-case

A keyword search over product descriptions, documentation pages, or support tickets returns poor results when users phrase queries differently from the indexed text. You need similarity-based retrieval that understands meaning, not just exact string matches.

## Context

Cloudflare Vectorize is a managed vector database built into the Workers platform. It stores high-dimensional floating-point vectors alongside arbitrary metadata and supports approximate nearest-neighbour (ANN) search via cosine similarity, dot product, or Euclidean distance. Vectors are generated by embedding models — Cloudflare Workers AI provides several (e.g., `@cf/baai/bge-base-en-v1.5`) at the edge with no external API calls required.

Typical pipeline:
1. At ingest time: chunk text → embed with Workers AI → upsert to Vectorize with metadata.
2. At query time: embed the user's query → search Vectorize → hydrate full records from source DB.

### 4. Embedding Generation Pipeline

```typescript
// src/embed.ts
import type { Env } from './types';

const MODEL = '@cf/baai/bge-base-en-v1.5';

export async function embedText(text: string, env: Env): Promise<number[]> {
  // Truncate to model's token limit before embedding
  const truncated = text.slice(0, 8000);

  const result = await env.AI.run(MODEL, {
    text: [truncated],
  }) as { data: number[][] };

  return result.data[0];
}

export async function embedBatch(texts: string[], env: Env): Promise<number[][]> {
  // Workers AI supports batching — more efficient than serial calls
  const result = await env.AI.run(MODEL, {
    text: texts.map((t) => t.slice(0, 8000)),
  }) as { data: number[][] };

  return result.data;
}
```

### 5. Upsert Documents with Metadata

```typescript
// src/ingest.ts
import type { Env, DocumentMetadata } from './types';
import { embedBatch } from './embed';

interface Document {
  id: string;
  title: string;
  body: string;
  url: string;
  source: string;
  created_at: string;
}

export async function ingestDocuments(docs: Document[], env: Env): Promise<void> {
  // Batch embed — Workers AI handles up to 100 texts per call
  const BATCH_SIZE = 50;

  for (let i = 0; i < docs.length; i += BATCH_SIZE) {
    const batch = docs.slice(i, i + BATCH_SIZE);
    const texts = batch.map((d) => `${d.title}\n\n${d.body}`);
    const vectors = await embedBatch(texts, env);

    const vectorizeInput: VectorizeVector[] = batch.map((doc, idx) => ({
      id: doc.id,
      values: vectors[idx],
      metadata: {
        title: doc.title,
        url: doc.url,
        source: doc.source,
        created_at: doc.created_at,
      } satisfies DocumentMetadata,
    }));

    // Upsert is idempotent — safe to re-run on re-index
    await env.VECTORIZE.upsert(vectorizeInput);
    console.log(`Upserted batch ${i / BATCH_SIZE + 1}: ${batch.length} vectors`);
  }
}
```

### 6. Query by Semantic Similarity

```typescript
// src/search.ts
import type { Env } from './types';
import { embedText } from './embed';

export interface SearchResult {
  id: string;
  score: number;
  title: string;
  url: string;
  source: string;
}

export async function semanticSearch(
  query: string,
  env: Env,
  options: {
    topK?: number;
    minScore?: number;
    filterSource?: string;
  } = {}
): Promise<SearchResult[]> {
  const { topK = 10, minScore = 0.5, filterSource } = options;

  const queryVector = await embedText(query, env);

  // Build metadata filter — Vectorize supports equality and range filters
  const filter: VectorizeVectorMetadataFilter | undefined = filterSource
    ? { source: { $eq: filterSource } }
    : undefined;

  const results = await env.VECTORIZE.query(queryVector, {
    topK,
    filter,
    returnMetadata: 'all',
    returnValues: false,   // Don't return raw vectors — wastes bandwidth
  });

  return results.matches
    .filter((m) => m.score >= minScore)
    .map((m) => ({
      id: m.id,
      score: m.score,
      title: (m.metadata as any)?.title ?? '',
      url: (m.metadata as any)?.url ?? '',
      source: (m.metadata as any)?.source ?? '',
    }));
}
```

### 7. Full Worker Handler

```typescript
// src/index.ts
import type { Env } from './types';
import { semanticSearch } from './search';
import { ingestDocuments } from './ingest';

export default {
  async fetch(request: Request, env: Env, ctx: ExecutionContext): Promise<Response> {
    const url = new URL(request.url);

    // POST /search — semantic query
    if (url.pathname === '/search' && request.method === 'POST') {
      const body = await request.json<{
        query: string;
        topK?: number;
        minScore?: number;
        source?: string;
      }>();

      if (!body.query?.trim()) {
        return Response.json({ error: 'query is required' }, { status: 400 });
      }

      const results = await semanticSearch(body.query, env, {
        topK: body.topK,
        minScore: body.minScore,
        filterSource: body.source,
      });

      return Response.json({ results });
    }

    // POST /ingest — index new documents (admin use)
    if (url.pathname === '/ingest' && request.method === 'POST') {
      const { documents } = await request.json<{ documents: any[] }>();
      ctx.waitUntil(ingestDocuments(documents, env));
      return Response.json({ status: 'ingestion started', count: documents.length });
    }

    // DELETE /vectors/:id — remove a single vector
    if (url.pathname.startsWith('/vectors/') && request.method === 'DELETE') {
      const id = url.pathname.split('/').pop()!;
      await env.VECTORIZE.deleteByIds([id]);
      return Response.json({ deleted: id });
    }

    return Response.json({ error: 'Not found' }, { status: 404 });
  },
};
```

// src/admin.ts — index introspection helpers
export async function getIndexInfo(env: Env): Promise<VectorizeIndexDetails> {
  // Returns dimension count, metric, vector count
  return env.VECTORIZE.describe();
}

export async function deleteVectors(ids: string[], env: Env): Promise<void> {
  // Batch delete — max 1000 IDs per call
  const BATCH = 1000;
  for (let i = 0; i < ids.length; i += BATCH) {
    await env.VECTORIZE.deleteByIds(ids.slice(i, i + BATCH));
  }
}

export async function getByIds(
  ids: string[],
  env: Env
): Promise<VectorizeMatches> {
  return env.VECTORIZE.getByIds(ids);
}

### 9. Result Re-ranking with Workers AI

```typescript
// src/rerank.ts — optional cross-encoder re-ranking pass
import type { Env, SearchResult } from './types';

export async function rerankResults(
  query: string,
  results: SearchResult[],
  env: Env,
  topN: number = 5
): Promise<SearchResult[]> {
  if (results.length === 0) return [];

  // Use a cross-encoder model for more precise relevance scoring
  // This is a second-pass over the top-K ANN candidates
  const reranked = await env.AI.run('@cf/baai/bge-reranker-base', {
    query,
    documents: results.map((r) => r.title),
  }) as { scores: number[] };

  return results
    .map((r, i) => ({ ...r, score: reranked.scores[i] }))
    .sort((a, b) => b.score - a.score)
    .slice(0, topN);
}
```

## Implementation Details

**Dimension alignment:** The vector dimensions declared at index creation must exactly match the model output. `bge-base-en-v1.5` produces 768 dimensions; `bge-large-en-v1.5` produces 1024. Mismatches cause upsert errors.

**ID uniqueness:** Vector IDs are strings up to 64 characters. Use stable, deterministic IDs (e.g., a hash of the content URL) so re-indexing the same document overwrites the old vector rather than creating a duplicate.

**Metadata filters:** Vectorize supports `$eq`, `$ne`, `$lt`, `$lte`, `$gt`, `$gte` operators on metadata fields. Filters are applied pre-ANN search to restrict the candidate set — they reduce recall if too restrictive.

**Index capacity:** Vectorize indexes support up to 5 million vectors at 768 dimensions per index (as of 2024). Plan sharding strategy early for large corpora.

**Cosine vs dot product:** Cosine normalises for magnitude — suitable when embedding magnitudes vary. Dot product is faster but requires normalised vectors to be equivalent. Most pre-trained embedding models produce L2-normalised vectors, making cosine and dot product equivalent.

## Anti-patterns

- Do not embed the user's raw query without any preprocessing — remove PII and normalise whitespace first.
- Do not set `topK` to a very large value (e.g., 1000) and filter in application code — Vectorize ANN cost scales with topK.
- Do not store the entire document body in metadata — metadata is limited to 10 KB per vector. Store a reference ID and fetch the full text from a separate store (D1, R2).
- Do not skip the `minScore` threshold — ANN always returns topK results even when they are semantically unrelated.

## Gotchas

- Upsert is eventually consistent. Freshly upserted vectors may not appear in queries for a few seconds.
- `deleteByIds` does not error if an ID does not exist — it silently succeeds.
- Workers AI model availability differs between `wrangler dev` (uses remote AI) and production. Test with `--remote` flag locally to confirm model behaviour.
- Metadata field names are case-sensitive in filter expressions.
