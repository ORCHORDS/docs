# ISO/IEC 22123-1:2023 Cloud Computing Overview and Vocabulary Governance

## Purpose

ISO/IEC 22123-1:2023, "Information technology — Cloud computing — Part 1: Concepts and vocabulary," provides the foundational vocabulary and concepts for the ISO/IEC 22123 series on cloud computing. The standard updates the cloud computing vocabulary aligned with the ISO/IEC 22123 series structure (22123-1 concepts, 22123-2 reference architecture, 22123-3 interoperability). This article governs the application of ISO/IEC 22123-1 vocabulary so the organization's cloud computing documentation uses the standard's terms consistently.

## Scope

The standard applies to any organization using or providing cloud computing. Within this knowledge base, the article covers the cloud computing concepts (cloud service consumer, cloud service provider, cloud service partner; cloud service deployment models — public, private, hybrid, community, multi-cloud; cloud service categories — IaaS, PaaS, SaaS, and the emerging categories the standard recognizes), and the vocabulary the standard defines. It does not cover the reference architecture (22123-2) or interoperability (22123-3); readers should consult those separately.

## Workflow

1. Adopt the ISO/IEC 22123-1 vocabulary for the organization's cloud computing documentation: policies, procedures, contracts, and architecture documents should use the terms the standard defines.
2. Distinguish the cloud service deployment models the standard defines:
   - Public cloud: services are open to the general public.
   - Private cloud: services are limited to a single organization.
   - Hybrid cloud: a composition of two or more clouds (private, public, community) bound together by technology that enables data and application portability.
   - Community cloud: services are limited to a community of consumers with shared concerns.
   - Multi-cloud: a deployment using multiple cloud providers.
3. Distinguish the cloud service categories the standard defines (IaaS, PaaS, SaaS) and any emerging categories the organization uses.
4. Use the roles the standard defines (consumer, provider, partner) consistently in contracts and architectures.
5. Document the organization's cloud usage using the standard's terms.

## Controls and evidence

Vocabulary controls include the documented adoption of the standard's terms, the cloud usage documentation, and the contract language that uses the standard's terms. Evidence includes the documentation itself and the internal glossary mapping.

## Validation

Validation should confirm the terms is applied across the organization, the cloud deployment models and service categories are correctly identified, and the roles are consistently used. Periodic audits of cloud documentation confirm consistency.

## Failure correction

Common failure modes: the cloud computing vocabulary is used loosely (correct: enforce the standard's terms); deployment models and service categories are conflated (correct: distinguish deployment model from service category); multi-cloud is confused with hybrid cloud (correct: distinguish "multi-cloud" — using multiple cloud providers — from "hybrid cloud" — combining public and private clouds with portability); consumer and partner roles are confused in contracts (correct: clarify roles in contracts using the standard's terms).

## Limitations

ISO/IEC 22123-1 provides vocabulary and concepts; it does not certify any cloud deployment. The standard does not prescribe specific technical implementations. The standard does not address sector-specific cloud regulations (financial services, government, healthcare); readers should overlay their sector requirements.

## Scope note

This article summarizes project-neutral platform use of ISO/IEC 22123-1:2023. It does not assert any specific deployment's conformance or claim any certification outcome.
