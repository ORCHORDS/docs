# GitHub Codespaces Cloudflare Workers Dev Environment

- **Date:** 2026-08-22
- **Author:** example.com
- **Status:** production

## Symptom / Use-case

A new contributor to a Cloudflare Workers project spends 30–60 minutes installing Node.js,
pnpm, wrangler, and miniflare before they can run a single test. On macOS the Rust toolchain
for WASM compilation adds another 20 minutes. A GitHub Codespaces devcontainer eliminates
this setup entirely: the contributor opens the repository in a browser and has a running
`wrangler dev` session within 90 seconds using a pre-built image.

## Context

GitHub Codespaces provisions Docker-based development environments described by
`.devcontainer/devcontainer.json`. For Cloudflare Workers projects the container needs
Node.js (LTS), pnpm, wrangler CLI, and optionally the Rust/wasm-pack toolchain. Miniflare
runs entirely in Node.js inside the container so no special kernel privileges are required.
Wrangler's `--local` flag for D1, KV, and R2 bindings uses SQLite/filesystem emulation,
which works out of the box inside a Codespace. Port forwarding auto-publishes the worker's
local HTTP port so you can preview the worker from your browser tab. Secret injection uses
Codespaces secrets mapped from the organisation or repository level — they appear as
environment variables at codespace startup.

## Setup Script

```bash
#!/usr/bin/env bash
# .devcontainer/setup.sh
set -euo pipefail

# Install pnpm via corepack (ships with Node.js 22)
corepack enable
corepack prepare pnpm@latest --activate

# Install project dependencies
pnpm install --frozen-lockfile

# Add wasm32 target if Rust feature is present
if command -v rustup &>/dev/null; then
  rustup target add wasm32-unknown-unknown
  cargo install wasm-pack --locked 2>/dev/null || true
fi

# Create local D1 and KV directories so wrangler dev doesn't prompt
mkdir -p .miniflare/d1 .miniflare/kv .miniflare/r2

# Populate .dev.vars from Codespaces secrets if they are set
cat > .dev.vars << 'EOF'
# Auto-generated by .devcontainer/setup.sh
# Add additional dev-only vars below; do NOT commit secrets here
EOF

if [[ -n "${SOME_API_KEY:-}" ]]; then
  echo "SOME_API_KEY=${SOME_API_KEY}" >> .dev.vars
fi

echo "Codespace setup complete. Run: pnpm dev"
```

## Wrangler Local Development with Bindings

Configure `wrangler.toml` so that `wrangler dev` inside the Codespace uses local persistence
directories that map to the paths created in the setup script.

```toml
# wrangler.toml (excerpt — local dev overrides)
name = "my-worker"
main = "src/index.ts"
compatibility_date = "2025-01-01"
compatibility_flags = ["nodejs_compat"]

[[d1_databases]]
binding = "DB"
database_name = "my-db"
database_id = "00000000-0000-0000-0000-000000000000"   # real ID for --remote
preview_database_id = "local"                           # miniflare local

[[kv_namespaces]]
binding = "CACHE"
id = "aaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaa"
preview_id = "local"

[dev]
port = 8787
local_protocol = "http"

[vars]
ENVIRONMENT = "development"
```

And the TypeScript worker can reference bindings with full type safety via the generated
types from `wrangler types`:

```typescript
// src/index.ts
export interface Env {
  DB: D1Database;
  CACHE: KVNamespace;
  ENVIRONMENT: string;
}

export default {
  async fetch(request: Request, env: Env, ctx: ExecutionContext): Promise<Response> {
    const url = new URL(request.url);

    if (url.pathname === "/health") {
      const result = await env.DB.prepare("SELECT 1 AS ok").first<{ ok: number }>();
      return Response.json({ status: "ok", db: result?.ok === 1, env: env.ENVIRONMENT });
    }

    return new Response("Not found", { status: 404 });
  },
} satisfies ExportedHandler<Env>;
```

## Anti-patterns

- Checking `CLOUDFLARE_API_TOKEN` into `.dev.vars` and committing the file — the secret is
  readable by anyone with repository access and appears in git history permanently.
- Using the full Rust install profile instead of `minimal` in the devcontainer feature —
  adds 1.5 GB to the image and doubles the prebuild time with no benefit for Workers
  development where only `wasm32-unknown-unknown` target is needed.
- Forwarding port 8787 as `openPreview` (the embedded simple browser) instead of
  `openBrowser` — the Cloudflare Workers response headers for `fetch` events include
  `cf-*` headers that the embedded preview strips, hiding useful debugging information.

## Gotchas

- Codespaces prebuilds cache the image state after `postCreateCommand` completes; if the
  setup script changes the prebuild must be manually triggered in repository settings, or the
  stale cached image is used for up to 7 days.
- `wrangler dev` binds to `0.0.0.0` by default inside the container; if another process
  already holds port 8787 (e.g., a background `node` process from a previous dev session),
  wrangler will silently bind to a random port — run `lsof -i :8787` before starting.
- The `CLOUDFLARE_API_TOKEN` Codespaces secret requires the `Workers Scripts: Edit` scope;
  the default "All resources" token from the Cloudflare dashboard often has excessive
  permissions — create a scoped token for Codespaces use.

## Verification

```bash
# Confirm wrangler version and that local dev starts cleanly
pnpm wrangler --version

# Start local dev and verify the health endpoint responds
pnpm dev &
sleep 5
curl -s http://localhost:8787/health | jq .

# Verify D1 local persistence directory was created
ls .miniflare/d1/

# Check that generated types match the wrangler.toml bindings
pnpm wrangler types
grep "DB: D1Database" worker-configuration.d.ts
```
