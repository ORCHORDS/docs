# GitHub Actions Release Artifact Distribution via Cloudflare R2

- Date: 2026-08-22
- Author: example.com
- Status: production

## Hosting Release Assets on R2 with Signed URLs and CDN Caching

GitHub Releases is convenient for small binaries attached directly to a tag, but it imposes a 2 GB per-asset limit, serves files from GitHub's infrastructure with no custom domain, and provides no CDN or signed-URL mechanism for access-controlled downloads. For teams shipping large build artefacts—compiled CLIs, SDK bundles, WASM modules, ML model weights—Cloudflare R2 is a natural complement: no egress fees, global CDN via a custom `r2.dev` domain or a Worker proxy, and fine-grained access control through presigned URLs generated by a Worker.

The workflow runs on every `v*` tag push: it builds the release artefacts, uploads them to R2 via the `aws s3 cp` CLI (R2 is S3-compatible), then creates a GitHub Release with download links pointing at a Workers endpoint that validates the caller's GitHub-issued token before generating a presigned URL. Wrangler deploy is coordinated in the same workflow to ensure the download Worker is up-to-date before the release is published.

CDN caching is handled by Cloudflare's Cache API inside the Worker: public artefacts (open-source builds) cache for 30 days; private artefacts bypass the cache and go straight to a presigned R2 URL that expires in 15 minutes.

## Context

- R2 bucket: `release-assets` with public access disabled
- Worker: `release-download` — validates GitHub token, returns presigned URL or proxies the stream
- CDN: Cloudflare cache via `Cache-Control: public, max-age=2592000` for public builds
- Auth: R2 S3-compatible API with `R2_ACCESS_KEY_ID` / `R2_SECRET_ACCESS_KEY` Actions secrets
- Wrangler: deployed in the same workflow before the GitHub Release is published

## GitHub Actions Workflow

```yaml
# .github/workflows/release.yml
name: Release

on:
  push:
    tags:
      - "v*"

permissions:
  contents: write   # create GitHub Release
  id-token: write   # OIDC for Wrangler

jobs:
  build-and-release:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4

      - uses: actions/setup-node@v4
        with:
          node-version: 20
          cache: pnpm

      - run: pnpm install --frozen-lockfile

      - name: Build release artefacts
        run: pnpm run build:release
        # Outputs: dist/my-cli-linux-x64, dist/my-cli-macos-arm64, dist/my-cli-windows-x64.exe

      - name: Upload artefacts to R2
        env:
          AWS_ACCESS_KEY_ID: ${{ secrets.R2_ACCESS_KEY_ID }}
          AWS_SECRET_ACCESS_KEY: ${{ secrets.R2_SECRET_ACCESS_KEY }}
          R2_ENDPOINT: https://<account-id>.r2.cloudflarestorage.com
          TAG: ${{ github.ref_name }}
        run: |
          aws s3 cp dist/ \
            "s3://release-assets/${TAG}/" \
            --recursive \
            --endpoint-url "$R2_ENDPOINT" \
            --no-progress

      - name: Deploy download Worker
        uses: cloudflare/wrangler-action@v3
        with:
          apiToken: ${{ secrets.CF_API_TOKEN }}
          command: deploy --env production

      - name: Create GitHub Release with R2 download links
        uses: actions/github-script@v7
        env:
          TAG: ${{ github.ref_name }}
          DOWNLOAD_BASE: https://releases.example.com/download
        with:
          script: |
            const tag = process.env.TAG;
            const base = process.env.DOWNLOAD_BASE;
            const assets = [
              "my-cli-linux-x64",
              "my-cli-macos-arm64",
              "my-cli-windows-x64.exe",
            ];
            const body = assets
              .map(a => `- ${a}`)
              .join("\n");

            await github.rest.repos.createRelease({
              owner: context.repo.owner,
              repo: context.repo.repo,
              tag_name: tag,
              name: `Release ${tag}`,
              body: `## Downloads\n\n${body}`,
              draft: false,
              prerelease: tag.includes("-rc"),
            });
```

## Download Worker with Presigned URL Generation

```ts
// src/download-worker.ts
import { AwsClient } from "aws4fetch";

export interface Env {
  R2_ACCESS_KEY_ID: string;
  R2_SECRET_ACCESS_KEY: string;
  R2_ACCOUNT_ID: string;
  R2_BUCKET: string;
  IS_PUBLIC: string; // "true" | "false"
}

const PRESIGN_TTL_SECONDS = 900; // 15 minutes for private assets

export default {
  async fetch(request: Request, env: Env): Promise<Response> {
    const url = new URL(request.url);
    // Expected path: /download/<tag>/<filename>
    const assetPath = url.pathname.replace(/^\/download\//, "");
    if (!assetPath) return new Response("Not Found", { status: 404 });

    const isPublic = env.IS_PUBLIC === "true";

    if (isPublic) {
      return servePublicAsset(env, assetPath);
    }

    // For private assets validate the caller has a valid GitHub token
    const token = request.headers.get("Authorization")?.replace(/^Bearer\s+/, "");
    if (!token || !(await validateGitHubToken(token))) {
      return new Response("Unauthorized", { status: 401 });
    }

    return generatePresignedRedirect(env, assetPath);
  },
};

async function servePublicAsset(env: Env, assetPath: string): Promise<Response> {
  const r2Url = `https://${env.R2_ACCOUNT_ID}.r2.cloudflarestorage.com/${env.R2_BUCKET}/${assetPath}`;

  const cache = caches.default;
  const cacheKey = new Request(r2Url);
  const cached = await cache.match(cacheKey);
  if (cached) return cached;

  const aws = new AwsClient({
    accessKeyId: env.R2_ACCESS_KEY_ID,
    secretAccessKey: env.R2_SECRET_ACCESS_KEY,
    service: "s3",
    region: "auto",
  });

  const r2Res = await aws.fetch(r2Url);
  if (!r2Res.ok) return new Response("Asset Not Found", { status: 404 });

  const response = new Response(r2Res.body, {
    headers: {
      "Content-Type": r2Res.headers.get("Content-Type") ?? "application/octet-stream",
      "Cache-Control": "public, max-age=2592000, immutable",
      "Content-Disposition": `attachment; filename="${assetPath.split("/").pop()}"`,
    },
  });

  await cache.put(cacheKey, response.clone());
  return response;
}

async function generatePresignedRedirect(env: Env, assetPath: string): Promise<Response> {
  const aws = new AwsClient({
    accessKeyId: env.R2_ACCESS_KEY_ID,
    secretAccessKey: env.R2_SECRET_ACCESS_KEY,
    service: "s3",
    region: "auto",
  });

  const r2Url = new URL(
    `/${env.R2_BUCKET}/${assetPath}`,
    `https://${env.R2_ACCOUNT_ID}.r2.cloudflarestorage.com`
  );
  r2Url.searchParams.set("X-Amz-Expires", String(PRESIGN_TTL_SECONDS));

  const signed = await aws.sign(new Request(r2Url.toString(), { method: "GET" }), {
    aws: { signQuery: true },
  });

  return Response.redirect(signed.url, 302);
}

async function validateGitHubToken(token: string): Promise<boolean> {
  const res = await fetch("https://api.github.com/user", {
    headers: { Authorization: `Bearer ${token}`, "User-Agent": "release-worker/1.0" },
  });
  return res.ok;
}
```

## CDN Caching Strategy

```toml
# wrangler.toml
name = "release-download"
main = "src/download-worker.ts"
compatibility_date = "2026-01-01"

[vars]
R2_ACCOUNT_ID = "<your-account-id>"
R2_BUCKET = "release-assets"
IS_PUBLIC = "true"

# R2_ACCESS_KEY_ID and R2_SECRET_ACCESS_KEY set via wrangler secret put

[[routes]]
pattern = "releases.example.com/download/*"
zone_name = "example.com"
```

Set a Cloudflare Cache Rule in the dashboard to cache `releases.example.com/download/*` at edge for 30 days, overriding the default no-cache for binary MIME types. For immutable versioned assets this avoids cache purge complexity—a new tag always maps to a new R2 prefix.

## Anti-patterns

- Attaching large artefacts (>100 MB) directly to a GitHub Release — GitHub enforces a hard 2 GB limit and has no CDN; R2 is a better fit for large binaries
- Using a long-lived R2 token stored in `wrangler.toml` — always use `wrangler secret put` and rotate tokens periodically
- Caching private artefacts at the CDN layer — ensure `Cache-Control: private, no-store` for token-gated downloads
- Not pinning the artefact path to the tag name — a mutable `latest/` prefix means old download links silently point to new binaries
- Deploying the Worker after publishing the release — the download links are live before the Worker handles them; always deploy the Worker first

## Gotchas

- R2 presigned URLs use AWS Signature V4; the `X-Amz-Expires` value is in seconds and the maximum is 604800 (7 days)
- `aws4fetch` must be bundled into the Worker since it is not a native Worker API
- `caches.default` is only available in Workers, not in the local `wrangler dev` sandbox — mock it in tests
- Cloudflare Cache API `cache.put` only caches responses with a status of 200; redirect responses (301, 302) are not cached
- The GitHub token validation call to `api.github.com/user` costs one API request per download for private assets; consider caching the validation result in Workers KV for 5 minutes with the token hash as the key

## Verification

```ts
// Confirm public asset is served and cache header is set
import { unstable_dev } from "wrangler";
import { describe, it, expect, beforeAll, afterAll } from "vitest";

describe("download worker", () => {
  let worker: Awaited<ReturnType<typeof unstable_dev>>;

  beforeAll(async () => {
    worker = await unstable_dev("src/download-worker.ts", {
      vars: { IS_PUBLIC: "true" },
      experimental: { disableExperimentalWarning: true },
    });
  });

  afterAll(() => worker.stop());

  it("returns Cache-Control: public for public assets", async () => {
    const res = await worker.fetch("/download/v1.0.0/my-cli-linux-x64");
    // Will 404 in test (no real R2), but header logic fires before the R2 call
    expect(res.headers.get("cache-control")).toMatch(/public/);
  });
});
```
