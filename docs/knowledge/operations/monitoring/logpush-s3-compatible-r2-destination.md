# Logpush S3-Compatible R2 Destination Configuration

Date: 2026-08-23 / Author: example.com / Status: production

---

## Symptom / Use-case

You want to stream Cloudflare Logpush data into an R2 bucket but use the
**S3-compatible API** endpoint rather than the native R2 Logpush destination
type. Common reasons:

- Your log-processing pipeline (Fluentd, Vector, AWS Glue) is already
  configured to read from S3-compatible endpoints and you want one unified
  integration.
- You need to fan out logs to multiple buckets in different accounts without
  duplicating a Logpush job.
- You want to test the pipeline locally using MinIO before switching to R2.

The S3-compatible approach uses Logpush's generic **S3 destination** type
pointed at R2's S3 endpoint (`https://<ACCOUNT_ID>.r2.cloudflarestorage.com`)
with R2-issued S3 credentials.

---

## Context

R2 exposes an S3-compatible API at:

```
https://<ACCOUNT_ID>.r2.cloudflarestorage.com/<BUCKET_NAME>
```

Logpush's S3 destination type sends multipart-uploaded `.gz` or uncompressed
NDJSON objects using AWS Signature Version 4. R2 accepts SigV4 with the
same bucket/key mechanics as AWS S3 — the only differences are the endpoint
hostname and the credential source.

R2 S3 credentials are separate from Cloudflare API tokens: you generate them
in the R2 dashboard under **Manage R2 API Tokens**, obtaining an
`Access Key ID` and `Secret Access Key`.

---

## Step 1: Create an R2 Bucket and S3 Credentials

```bash
# Create the destination bucket (via wrangler)
npx wrangler r2 bucket create logpush-raw

# Generate R2 S3 credentials in the dashboard:
# Dashboard → R2 → Manage R2 API tokens → Create API token
# Select: Object Read & Write on bucket "logpush-raw"
# Save ACCESS_KEY_ID and SECRET_ACCESS_KEY
```

---

## Step 2: Create the Logpush Job via API

```bash
curl -X POST "https://api.cloudflare.com/client/v4/zones/${ZONE_ID}/logpush/jobs" \
  -H "Authorization: Bearer ${CF_API_TOKEN}" \
  -H "Content-Type: application/json" \
  -d '{
    "name": "workers-logs-to-r2-s3",
    "destination_conf": "s3://logpush-raw/logs?region=auto&access-key-id='"${R2_ACCESS_KEY_ID}"'&secret-access-key='"${R2_SECRET_ACCESS_KEY}"'&endpoint='"${CF_ACCOUNT_ID}"'.r2.cloudflarestorage.com",
    "dataset": "workers_trace_events",
    "logpull_options": "fields=Event,EventTimestampMs,Outcome,Exceptions,Logs,ScriptName",
    "enabled": true,
    "frequency": "high",
    "output_options": {
      "field_delimiter": "\n",
      "record_delimiter": "\n",
      "timestamp_format": "unixnano",
      "batch_prefix": "",
      "batch_suffix": ""
    }
  }'
```

### destination_conf breakdown

| Parameter | Value | Notes |
|-----------|-------|-------|
| `s3://` | scheme | tells Logpush to use S3 protocol |
| `logpush-raw` | bucket name | R2 bucket created above |
| `/logs` | key prefix | objects stored under this path |
| `region=auto` | AWS region | R2 requires `auto`; any other value fails |
| `access-key-id` | R2 S3 key | from R2 API token |
| `secret-access-key` | R2 S3 secret | from R2 API token |
| `endpoint` | `<ACCOUNT_ID>.r2.cloudflarestorage.com` | overrides AWS endpoint |

## Step 3: Verify Ownership (first-time setup only)

Cloudflare requires a one-time ownership proof before enabling a new job.
The proof is generated by creating the job with `"enabled": false`, then:

```bash
# 1. Get the ownership challenge token
curl -X POST "https://api.cloudflare.com/client/v4/zones/${ZONE_ID}/logpush/ownership" \
  -H "Authorization: Bearer ${CF_API_TOKEN}" \
  -H "Content-Type: application/json" \
  -d '{"destination_conf":"s3://logpush-raw/logs?region=auto&access-key-id=...&secret-access-key=...&endpoint='"${CF_ACCOUNT_ID}"'.r2.cloudflarestorage.com"}'

# Cloudflare writes a file ownership-challenge-<hash>.txt to the bucket.
# 2. Read it from R2 using wrangler or the S3 API:
npx wrangler r2 object get logpush-raw/logs/ownership-challenge-<hash>.txt

# 3. Submit the token from that file to validate
curl -X POST "https://api.cloudflare.com/client/v4/zones/${ZONE_ID}/logpush/ownership/validate" \
  -H "Authorization: Bearer ${CF_API_TOKEN}" \
  -H "Content-Type: application/json" \
  -d '{"destination_conf":"...","ownership_challenge":"<TOKEN_FROM_FILE>"}'
```

## Step 4: Monitor Job Health with a Worker

```typescript
export interface Env {
  CF_API_TOKEN: string;
  CF_ZONE_ID: string;
  ALERT_WEBHOOK_URL: string;
}

export default {
  async scheduled(_event: ScheduledEvent, env: Env, ctx: ExecutionContext): Promise<void> {
    ctx.waitUntil(checkLogpushHealth(env));
  },
};

interface LogpushJob {
  id: number;
  name: string;
  enabled: boolean;
  last_complete?: string;
  last_error?: string;
  error_message?: string;
}

async function checkLogpushHealth(env: Env): Promise<void> {
  const res = await fetch(
    `https://api.cloudflare.com/client/v4/zones/${env.CF_ZONE_ID}/logpush/jobs`,
    { headers: { Authorization: `Bearer ${env.CF_API_TOKEN}` } },
  );
  const { result: jobs } = await res.json<{ result: LogpushJob[] }>();

  for (const job of jobs) {
    if (!job.enabled) continue;

    const lastComplete = job.last_complete ? new Date(job.last_complete) : null;
    const ageMinutes   = lastComplete
      ? (Date.now() - lastComplete.getTime()) / 60_000
      : Infinity;

    const stale = ageMinutes > 30;
    const hasError = Boolean(job.error_message);

    if (stale || hasError) {
      await fetch(env.ALERT_WEBHOOK_URL, {
        method: "POST",
        headers: { "Content-Type": "application/json" },
        body: JSON.stringify({
          text: `Logpush job "${job.name}" (id: ${job.id}) ${
            hasError ? `error: ${job.error_message}` : `stale: last complete ${Math.round(ageMinutes)} min ago`
          }`,
        }),
      });
    }
  }
}
```

## Object Layout in R2

Logpush writes objects with auto-generated keys:

```
logs/20260823T120000Z_20260823T121000Z_<hash>.log.gz
```

When using a custom prefix (`/logs`) the path becomes:
```
logs/20260823T120000Z_20260823T121000Z_<hash>.log.gz
```

Objects are NDJSON (one JSON object per line) gzip-compressed by default.
Set `compression: none` in `output_options` if your consumer cannot
decompress on the fly.

---

## Anti-patterns

**Using a non-`auto` region value.**
R2 does not support AWS region strings. Passing `region=us-east-1` in the
destination_conf string causes every batch to fail with a signature mismatch.
Always use `region=auto`.

**Using a Cloudflare API token as the S3 credential.**
R2 S3 credentials (`Access Key ID` / `Secret Access Key`) are separate from
Cloudflare API bearer tokens. Attempting to use a bearer token as an AWS
access key fails with 403.

**Configuring the endpoint as `r2.cloudflarestorage.com` without the account prefix.**
The full endpoint must include your account ID subdomain:
`<ACCOUNT_ID>.r2.cloudflarestorage.com`. Without it, the request routes to
public R2 infrastructure that cannot resolve your private bucket.

**Omitting the ownership verification step.**
Logpush jobs created with `"enabled": true` and an unverified destination
remain disabled silently. Always verify ownership before enabling.

---

## Gotchas

- R2's S3-compatible API supports multipart upload (which Logpush uses for
  large batches) but has a minimum part size of 5 MB except for the last
  part. Logpush handles this internally.
- Logpush delivers batches on a best-effort basis — it does not guarantee
  exactly-once delivery. Design your log consumer idempotently using the
  filename timestamp as a deduplication key.
- `last_complete` in the job status reflects when Logpush last successfully
  closed a batch, not when it last attempted delivery.
- R2 S3 credentials do not expire by default; rotate them periodically and
  update the job's `destination_conf` via a PATCH request.

## Verification

```bash
# After enabling the job, wait 2 minutes then list objects
aws s3 ls s3://logpush-raw/logs/ \
  --endpoint-url "https://${CF_ACCOUNT_ID}.r2.cloudflarestorage.com" \
  --no-sign-request \
  --region auto

# Or via wrangler
npx wrangler r2 object list logpush-raw --prefix logs/

# Decompress and inspect a batch
aws s3 cp s3://logpush-raw/logs/<file>.log.gz - \
  --endpoint-url "https://${CF_ACCOUNT_ID}.r2.cloudflarestorage.com" \
  | zcat | head -5
```

Confirm each line is valid JSON containing the fields specified in
`logpull_options`.
