# opentofu-migration-from-terraform

In 2023 HashiCorp switched Terraform to the BSL license; in 2024 Linux
Foundation forked OpenTofu under MPL/registry freeze. By 2026 many teams are
migrating off Terraform `>= 1.6` to OpenTofu to avoid BSL entanglement on
their internal platform products. This article covers the real migration
friction.

## Symptom

- `tofu plan` fails with `Error: Failed to query available provider packages`
  on a registry version that worked under Terraform.
- `tofu init` works, but `tofu plan` shows a huge diff trying to replace
  resources that were never touched.
- A teammate's CI uses `terraform` binary, another uses `tofu` — state file
  version mismatch warnings appear.
- The provider you depend on publishes a Terraform-only build and the OpenTofu
  registry mirror lacks the version you pinned.
- After switching, the CI cache serves stale `.terraform.lock.hcl` that won't
  validate under the new binary.

## Why Migrate

- BSL prohibits using Terraform to build competitive hosted offerings. If your
  company ships an internal developer platform (IDP) or a managed service,
  legal may flag Terraform usage.
- OpenTofu is a drop-in for Terraform up to 1.5.x. After 1.6 the binaries
  diverge: OpenTofu adds features (e.g. `tofu test`, early decrypt) that
  Terraform may or may not match.
- OpenTofu registry is a separate mirror; providers must be republished there.
  Most major ones (AWS, GCP, Azure, K8s, Vault) are. Niche ones may not be.

## Migration Checklist

1. **Audit providers.** List every provider in your state:
   ```bash
   terraform providers
   ```
   Cross-check each against <https://search.opentofu.org>. Anything missing is
   a blocker — file an issue with the upstream maintainer or vendor.
2. **Pin state version.** OpenTofu reads Terraform state up to current. Do not
   downgrade; do not run `terraform 1.5` and `tofu 1.7` against the same state
   concurrently.
3. **Replace the binary in PATH.** OpenTofu ships `tofu`. Symlink or wrapper:
   ```bash
   # keep legacy scripts that call `terraform` working
   ln -s "$(which tofu)" /usr/local/bin/terraform
   ```
4. **Regenerate lockfile under OpenTofu.**
   ```bash
   rm .terraform.lock.hcl
   tofu init -upgrade
   ```
   Commit the new lockfile. Mixing a lockfile generated by Terraform 1.7 with
   OpenTofu 1.7 can produce spurious provider hash mismatches.
5. **Run `tofu plan` against a scratch workspace first.** The plan should show
   **zero changes** if the migration is clean. Any diff = investigate before
   touching prod state.

## Fix: Provider registry mismatch

```hcl
# before — works under Terraform, may 404 under OpenTofu
terraform {
  required_providers {
    random = {
      source  = "hashicorp/random"
      version = "3.6.0"
    }
  }
}
```

Under OpenTofu the same `source = "hashicorp/random"` resolves via the OpenTofu
registry, which mirrors most `hashicorp/*` providers. If you hit a 404:

```hcl
# explicit OpenTofu registry namespace (rarely needed)
terraform {
  required_providers {
    random = {
      source  = "registry.opentofu.org/hashicorp/random"
      version = "3.6.0"
    }
  }
}
```

For truly unmigrated providers, fork and republish, or pin to the last version
that was mirrored and open an upstream issue.

## Fix: CI matrix to validate both during transition

```yaml
# .github/workflows/plan.yml
strategy:
  matrix:
    binary: [terraform, opentofu]
steps:
  - uses: actions/checkout@v4
  - name: Install
    run: |
      if [ "${{ matrix.binary }}" = "opentofu" ]; then
        curl -fsSL https://get.opentofu.org/install.sh | sh
      else
        curl -fsSL https://releases.hashicorp.com/terraform/1.9.8/terraform_1.9.8_linux_amd64.zip -o tf.zip
        unzip tf.zip && install terraform /usr/local/bin/
      fi
  - name: Plan
    run: |
      BIN=${{ matrix.binary == 'opentofu' && 'tofu' || 'terraform' }}
      $BIN init -input=false
      $BIN plan -detailed-exitcode -out=plan.bin
```

`-detailed-exitcode` exits non-zero on diff. Both binaries should agree on
"no changes" before you cut over prod.

## Gotchas

- **Feature divergence after 1.6.** Terraform added `removed` blocks, loopable
  `import`; OpenTofu added `tofu test` enhancements and early provider
  downloads. HCL written for one may not parse under the other. CI on both
  binaries is the only safety net.
- **State locking backend compatibility.** S3 + DynamoDB lock, GCS, Azure Blob,
  and HTTP backends work identically. Consul and `pg` backends had subtle
  divergences in 1.7 — verify your backend is on the OpenTofu support matrix.
- **Do not run Terraform and OpenTofu against the same state concurrently.**
  The lock prevents corruption, but plan output can differ because each
  interprets the schema with its own provider version. Pick one per workspace.
- **`terraform`-named wrapper scripts hide which binary is running.** Always
  `tofu version` / `terraform version` in CI logs so the audit trail is clear.
  A 6-month-later incident investigation must be able to tell which engine
  applied state.
- **Vendor plugins shipped as private Terraform registry only.** Enterprise
  Terraform providers from vendors who never republished to OpenTofu are the
  most common blocker. Engage vendor support early; the answer is usually
  "we'll publish next quarter."
- **Atlantis / Terrateam / Spacelift config.** These tools hardcode the
  `terraform` command. Most added a `terraform_binary: tofu` setting in 2024 —
  set it once globally, or per-repo.
- **`tflint` and `tfsec`/`trivy` work on HCL, not the binary**, so they're
  unaffected. But check whether your policy-as-code tool fetches provider
  schemas via the Terraform or OpenTofu registry — different schemas can
  produce different violations.
- **Downgrading back is harder than upgrading.** OpenTofu may write state with
  fields Terraform doesn't recognize. Snapshot state with `tofu state pull >
   pre-migration.tfstate` before cutover, and keep that backup for a quarter.

## Decision Rule

Migrate if: you ship a platform/managed service and legal flagged BSL, or you
want features OpenTofu shipped first. Stay on Terraform if: a critical
provider is Terraform-only and upstream won't republish, or your org has a
HashiCorp enterprise contract that locks in tooling. Both are mature in 2026;
this is a procurement/legal call more than a technical one.
