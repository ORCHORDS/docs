# SLSA Build Provenance for Workers CI/CD

- **Date**: 2026-08-22
- **Author**: example.com
- **Status**: production

---

## Symptom / Use-case

A software supply chain audit (NIST SP 800-161r1, EU Cyber Resilience Act Article 13, FedRAMP Rev 5 SA-12) asks you to demonstrate that the Cloudflare Worker code running in production was built from the exact source commit it claims, was not tampered with between the build and the deployment, and that the build itself ran in a verifiable, isolated environment. Without provenance attestations, you can only provide "trust me" assertions. Downstream enterprise customers and government procurement officers increasingly require SLSA Build Level 2 or 3 as a contractual condition.

---

## Context

SLSA (Supply chain Levels for Software Artifacts) is a security framework maintained by the OpenSSF that defines four graduated levels of build integrity:

| Level | Key guarantee |
|---|---|
| L1 | Provenance exists (signed by builder) |
| L2 | Provenance generated by a hosted CI service; source tracked in a VCS |
| L3 | Hardened build platform; no fork of build instructions permitted at runtime |
| L4 | Hermetic, isolated build; reproducible |

For Cloudflare Workers deployments, reaching **SLSA Build Level 2** is achievable with GitHub Actions or GitLab CI using the official SLSA GitHub Generator. Level 3 requires a hardened runner (no network egress, ephemeral, no persistent home directory).

The provenance artifact is an in-toto attestation (DSSE-signed JSON-LD document) that records:
- The exact source commit SHA
- Build inputs (workflow file SHA, runner image digest)
- Build environment metadata
- The digest of the output artifact (the `.js` / `.wasm` Worker bundle)

Verification is done with `slsa-verifier` before any deployment step.

## GitHub Actions Workflow with SLSA Provenance Generation

### 3.1 Generating Provenance for a Workers Bundle

```yaml
# .github/workflows/deploy-worker.yml
name: Build and Deploy Worker with SLSA Provenance

on:
  push:
    branches: [main]
  workflow_dispatch:

permissions:
  contents: read
  id-token: write    # Required for OIDC token (SLSA provenance signing)
  attestations: write # Required for GitHub Attestations API

jobs:
  build:
    name: Build Worker Bundle
    runs-on: ubuntu-latest
    outputs:
      artifact-digest: ${{ steps.hash.outputs.digest }}
    steps:
      - uses: actions/checkout@v4
        with:
          fetch-depth: 0

      - uses: actions/setup-node@v4
        with:
          node-version: '22'
          cache: 'npm'

      - name: Install dependencies
        run: npm ci --ignore-scripts  # --ignore-scripts prevents supply-chain attacks in postinstall

      - name: Build Worker bundle
        run: npx wrangler deploy --dry-run --outdir dist/
        # --dry-run produces the bundle without deploying; --outdir writes to dist/

      - name: Compute SHA-256 digest of bundle
        id: hash
        run: |
          DIGEST=$(sha256sum dist/worker.js | awk '{print $1}')
          echo "digest=sha256:${DIGEST}" >> "$GITHUB_OUTPUT"
          echo "Bundle digest: sha256:${DIGEST}"

      - name: Upload build artifact
        uses: actions/upload-artifact@v4
        with:
          name: worker-bundle
          path: dist/
          if-no-files-found: error

  provenance:
    name: Generate SLSA Provenance
    needs: build
    permissions:
      id-token: write
      attestations: write
      contents: read
    uses: slsa-framework/slsa-github-generator/.github/workflows/generator_generic_slsa3.yml@v2.1.0
    with:
      base64-subjects: ${{ needs.build.outputs.artifact-digest }}
      upload-assets: true
      upload-tag-name: ${{ github.ref_name }}

  deploy:
    name: Deploy to Cloudflare Workers
    needs: [build, provenance]
    runs-on: ubuntu-latest
    environment: production
    steps:
      - uses: actions/checkout@v4

      - name: Download worker bundle
        uses: actions/download-artifact@v4
        with:
          name: worker-bundle
          path: dist/

      - name: Download provenance attestation
        uses: actions/download-artifact@v4
        with:
          name: ${{ needs.provenance.outputs.provenance-name }}
          path: provenance/

      - name: Verify provenance before deploy
        run: |
          # Install slsa-verifier
          curl -sLo /usr/local/bin/slsa-verifier \
            "https://github.com/slsa-framework/slsa-verifier/releases/download/v2.7.0/slsa-verifier-linux-amd64"
          chmod +x /usr/local/bin/slsa-verifier

          slsa-verifier verify-artifact \
            dist/worker.js \
            --provenance-path provenance/*.intoto.jsonl \
            --source-uri "github.com/${{ github.repository }}" \
            --source-branch main \
            --builder-id "https://github.com/slsa-framework/slsa-github-generator/.github/workflows/generator_generic_slsa3.yml@refs/tags/v2.1.0"

          echo "Provenance verified. Proceeding with deployment."

      - name: Deploy Worker
        env:
          CLOUDFLARE_API_TOKEN: ${{ secrets.CF_API_TOKEN }}
          CLOUDFLARE_ACCOUNT_ID: ${{ secrets.CF_ACCOUNT_ID }}
        run: npx wrangler deploy --env production

      - name: Record deployment evidence
        run: |
          cat > deployment-evidence.json <<EOF
          {
            "deployedAt": "$(date -u +%Y-%m-%dT%H:%M:%SZ)",
            "commitSha": "${{ github.sha }}",
            "workflow": "${{ github.workflow }}",
            "runId": "${{ github.run_id }}",
            "bundleDigest": "${{ needs.build.outputs.artifact-digest }}",
            "provenanceVerified": true,
            "slsaLevel": "3"
          }
          EOF
          cat deployment-evidence.json
```

## Storing and Querying Deployment Provenance

Store provenance metadata in D1 for audit queries across deployment history.

```typescript
// src/provenance-registry.ts — a Worker that accepts deployment evidence POSTs
// Called by the CI/CD pipeline after successful deployment

interface DeploymentEvidence {
  deployedAt: string;
  commitSha: string;
  workflow: string;
  runId: string;
  bundleDigest: string;
  provenanceVerified: boolean;
  slsaLevel: string;
}

export async function recordDeployment(
  env: Env,
  evidence: DeploymentEvidence
): Promise<void> {
  await env.DB.prepare(`
    INSERT INTO deployment_provenance
      (commit_sha, deployed_at, workflow, run_id, bundle_digest,
       provenance_verified, slsa_level, created_at)
    VALUES (?, ?, ?, ?, ?, ?, ?, unixepoch())
  `).bind(
    evidence.commitSha,
    evidence.deployedAt,
    evidence.workflow,
    evidence.runId,
    evidence.bundleDigest,
    evidence.provenanceVerified ? 1 : 0,
    evidence.slsaLevel
  ).run();
}

export async function assertCurrentDeploymentIsVerified(env: Env): Promise<void> {
  const latest = await env.DB.prepare(`
    SELECT provenance_verified, slsa_level, deployed_at
    FROM deployment_provenance
    ORDER BY created_at DESC
    LIMIT 1
  `).first<{ provenance_verified: number; slsa_level: string; deployed_at: string }>();

  if (!latest || !latest.provenance_verified) {
    // Log to audit trail and optionally raise an incident
    console.error('SECURITY: Current deployment has no verified SLSA provenance');
    throw new Error('Unverified deployment detected');
  }
}
```

```sql
-- migrations/0001_provenance.sql
CREATE TABLE IF NOT EXISTS deployment_provenance (
  id                   INTEGER PRIMARY KEY AUTOINCREMENT,
  commit_sha           TEXT    NOT NULL,
  deployed_at          TEXT    NOT NULL,
  workflow             TEXT    NOT NULL,
  run_id               TEXT    NOT NULL,
  bundle_digest        TEXT    NOT NULL,
  provenance_verified  INTEGER NOT NULL DEFAULT 0,
  slsa_level           TEXT    NOT NULL DEFAULT 'L0',
  created_at           INTEGER NOT NULL DEFAULT (unixepoch())
);

CREATE INDEX IF NOT EXISTS idx_prov_commit ON deployment_provenance(commit_sha);
CREATE INDEX IF NOT EXISTS idx_prov_created ON deployment_provenance(created_at);
```

## Dependency Pinning and SBOM Integration

SLSA provenance is most valuable when combined with a Software Bill of Materials (SBOM) that captures the exact versions of all npm packages included in the bundle.

```yaml
# Extend the build job with SBOM generation
      - name: Generate SBOM
        run: |
          npx @cyclonedx/cyclonedx-npm \
            --output-file sbom.cdx.json \
            --output-format JSON \
            --spec-version 1.6 \
            --package-lock-only

      - name: Upload SBOM artifact
        uses: actions/upload-artifact@v4
        with:
          name: sbom
          path: sbom.cdx.json
```

Pin all direct and transitive dependencies using `npm ci` (which respects `package-lock.json` exactly). Never use `npm install` in CI. Enable Dependabot or Renovate to propose automated lock-file updates with associated PR provenance.

---

## Anti-patterns

- **Running `wrangler deploy` directly in the build job.** This bypasses the provenance generation step and produces an unverified deployment. Always split build, provenance, and deploy into separate jobs with gated dependencies.
- **Using `actions/upload-artifact` without `if-no-files-found: error`.** A failed build that produces no bundle will silently upload an empty artifact, and the provenance will attest to an empty digest. Always fail fast.
- **Signing provenance with a long-lived key stored in a secret.** The SLSA GitHub Generator uses ephemeral OIDC-derived Sigstore keys, which are far more tamper-resistant than a static `GPG_PRIVATE_KEY` secret. Avoid rolling your own signing.
- **Trusting `package.json` version ranges in CI.** `^1.2.3` in `package.json` may resolve to different versions on different runs. Always commit and use `package-lock.json` at version 3 (npm ≥ 7).
- **Not preserving the `.intoto.jsonl` provenance file as a release asset.** If the attestation is ephemeral, it cannot be verified later by an auditor.

---

## Gotchas

- **`generator_generic_slsa3.yml` requires reusable workflow trust.** It must be referenced at a pinned SHA tag, not a branch, to satisfy SLSA L3 isolation requirements. GitHub's reusable workflow isolation prevents the calling workflow from injecting environment variables into the generator.
- **`--dry-run` in wrangler does not produce the identical bundle as a live deploy.** Some source map generation and asset upload steps are skipped. Verify that the bundle digest computed during dry-run matches what is deployed; for critical workloads, compute the digest from the actual deploy output instead.
- **Cloudflare does not yet expose a signed deployment receipt.** The `wrangler deploy` command returns a deployment ID and version UUID (available via `wrangler versions list`) that you can store as additional evidence. The Cloudflare Deployments API (`GET /accounts/{id}/workers/scripts/{name}/deployments`) is the authoritative record.
- **SLSA L3 requires a hermetic build.** GitHub's hosted runners have outbound internet access, which technically precludes hermetic classification. For true L3 hermetic, use GitHub's container-based runners with network policies, or a self-hosted runner that blocks egress.

## Verification

```bash
# 1. Download provenance from GitHub release assets
gh release download v1.2.3 --pattern "*.intoto.jsonl" --dir /tmp/prov

# 2. Verify locally
slsa-verifier verify-artifact dist/worker.js \
  --provenance-path /tmp/prov/worker-bundle.intoto.jsonl \
  --source-uri "github.com/your-org/your-repo" \
  --source-branch main

# Expected output:
# Verified build using builder "https://github.com/slsa-framework/slsa-github-generator/..." at SLSA level 3

# 3. Query D1 deployment history for audit evidence
npx wrangler d1 execute prod-db \
  --command "SELECT commit_sha, deployed_at, slsa_level, provenance_verified FROM deployment_provenance ORDER BY created_at DESC LIMIT 10;"

# 4. Verify SBOM is current
cat sbom.cdx.json | jq '.metadata.timestamp'
```
