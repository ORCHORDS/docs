# OWASP Abuse Case Governance Profile

## Purpose

Define how teams should govern use of the current OWASP **Abuse Case** guidance without converting a public source into an unsupported claim of compliance or implementation.

## Authoritative source

- https://github.com/OWASP/CheatSheetSeries/blob/master/cheatsheets/Abuse_Case_Cheat_Sheet.md
- Source location reviewed: 2026-09-23

## Governance requirements

1. The current upstream sheet must be reviewed before a control or engineering requirement is derived from it.
2. Applicability must be documented for the actual system or process in scope.
3. Local requirements must be testable and linked to implementation or operational evidence.
4. Non-applicable recommendations must carry a rationale.
5. Exceptions must identify an owner, reason, compensating measure when relevant, and a review trigger.
6. Material architecture, dependency, identity, or data-flow changes trigger re-evaluation.
7. Public documentation must distinguish guidance, planned work, verified implementation, and external certification.

## Evidence expectations

A review record should contain source retrieval date, scope, applicability decisions, linked evidence, exceptions, reviewer, and next trigger.

## Assurance boundary

This profile is governance guidance. It does not state that any system conforms to OWASP or that a recommendation is implemented.
