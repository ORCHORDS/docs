# IEEE 1028-2008 Software Reviews and Inspections Governance

## Purpose

IEEE 1028-2008 defines five types of software reviews: management reviews, technical reviews, inspections, walkthroughs, and audits. Governance ensures that reviews are planned, conducted, and recorded according to a documented process, that reviewers are competent, and that review findings are tracked to closure.

## Current context and source status

IEEE 1028-2008 was published as a revision of IEEE 1028-1997. The standard is a process standard, not a certifiable standard. It is widely used as a reference for software review practices. Verify the current edition before treating any clause identifier as a current requirement.

## Governance workflow and controls

### 1. Select the review type

Select the appropriate review type based on the purpose:

- management reviews evaluate the project's status against the plan;
- technical reviews evaluate the technical adequacy of a product;
- inspections identify defects through a structured, formal process;
- walkthroughs educate reviewers and authors;
- audits confirm conformance with standards.

### 2. Define review entry and exit criteria

Define the entry criteria for each review (preconditions, materials, attendees) and exit criteria (findings dispositioned, follow-up actions assigned). Enforce the criteria.

### 3. Train reviewers

Ensure reviewers are trained in the review process, the review technique (for inspections), and the technical domain. Document training.

### 4. Conduct reviews

Follow the documented process for each review type. For inspections, follow the six-step process: planning, overview, individual preparation, inspection meeting, rework, follow-up. Record attendance, materials, findings, and decisions.

### 5. Track findings

Maintain a log of review findings with severity, owner, target date, and disposition. Verify closure. Track trends over time.

### 6. Use review metrics

Collect review metrics: preparation time, inspection rate, defect density, rework time. Use metrics to improve the review process.

### 7. Maintain records

Retain review records per the documented retention policy. Maintain review history to support process improvement.

## Validation and evidence

- Review process document.
- Reviewer training records.
- Review records per review.
- Findings log with closure evidence.
- Review metrics reports.

## Failure correction

Common defects include skipped review preparation, findings without owners, and reviews held for ceremony without driving improvement. Corrective actions include mandatory preparation verification, owner assignment enforcement, and a findings-to-improvement linkage review.

## Limitations

- IEEE 1028-2008 is a process standard, not a certifiable standard.
- Inspection requires dedicated reviewer time; budget accordingly.
- Review metrics are sensitive to process definition.
- The standard does not prescribe review tools.
