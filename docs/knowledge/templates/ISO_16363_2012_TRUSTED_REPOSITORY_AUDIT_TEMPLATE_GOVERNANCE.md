# ISO 16363:2012 Trusted Repository Audit Template Governance

## Purpose

ISO 16363:2012 (CCSDS 652.0-M-1), "Space data and information transfer systems — Audit and certification of trustworthy digital repositories," defines the metrics by which a digital repository can be audited against the OAIS reference model (ISO 14721). The standard identifies 109 metrics organized into three sections: Organizational Infrastructure, Digital Object Management, and Technologies and Technical Infrastructure. This article governs the application of ISO 16363 as a template for repository self-assessment or formal audit so the repository can demonstrate trustworthiness to its designated community.

## Scope

The standard applies to digital repositories that have a long-term preservation obligation. Within this knowledge base, the article covers the three audit sections and their metric categories, the audit process, the evidence collection per metric, and the documentation of audit findings. It does not certify repositories; an independent auditor or self-audit produces the assessment against the standard's metrics.

## Workflow

1. Establish the scope of the audit: which repository, which designated community, which timeframe.
2. Review the three sections:
   - Organizational Infrastructure (e.g., governance, staffing, funding sustainability, policies, consumer support).
   - Digital Object Management (e.g., submission, preservation description information, ingest, access, long-term preservation planning).
   - Technologies and Technical Infrastructure (e.g., infrastructure, security, preservation tools).
3. For each metric, collect the evidence the standard specifies. The standard is explicit about what counts as evidence for each metric (a document, a record, a procedure, a demonstration).
4. Apply the rating scale the standard defines for each metric. Ratings indicate the level of compliance or non-compliance.
5. Aggregate the findings into an audit report. The report should describe the repository's compliance with each metric, the evidence collected, and any non-conformities.
6. Take corrective action on identified non-conformities and track them to closure.

## Controls and evidence

Audit evidence is per metric: a policy, a procedure, a plan, a record, a demonstration. The repository must be able to produce the evidence for each metric to support an audit. The audit report itself is evidence of the audit's performance.

## Validation

Validation should confirm the audit scope is documented, evidence is collected for each metric, the rating scale is applied consistently, non-conformities are identified and addressed, and the audit report is reviewed and accepted. Independent review of the audit findings provides additional assurance.

## Failure correction

Common failure modes: the repository collects evidence reactively rather than continuously (corrective: maintain evidence as part of normal operations); ratings are inflated relative to the evidence (corrective: apply the rating scale honestly); non-conformities are listed but not tracked (corrective: maintain a corrective action register and track to closure); the audit is performed once without follow-up (corrective: schedule periodic re-audit and track the corrective actions between audits).

## Limitations

ISO 16363 is an audit standard; it does not certify repositories (the certification scheme is the CoreTrustSeal / nestor / DIN 31625 schemes that reference 16363). The standard does not define the substantive preservation methods; the repository selects those. The audit is point-in-time; the repository's compliance must be sustained.

## Scope note

This article summarizes project-neutral use of ISO 16363:2012 as a template. It does not assert any specific repository's certification or claim any audit outcome.
