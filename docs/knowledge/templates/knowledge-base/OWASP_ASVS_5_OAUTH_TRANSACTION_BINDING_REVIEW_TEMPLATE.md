## Review checks

- [ ] Authorization response values are accepted only when they correspond to an authorization flow initiated by the same user-agent session and transaction. *(ASVS V10.1.2)*
- [ ] Client-generated transaction secrets such as PKCE `code_verifier`, `state`, or OIDC `nonce` are not guessable. *(ASVS V10.1.2)*
- [ ] Those values are unique/specific to the authorization transaction and are securely bound to the client and originating user-agent session. *(ASVS V10.1.2)*
- [ ] For OAuth authorization-code flow, browser-based request-forgery/CSRF protection is implemented using PKCE or validated `state` as applicable to the design. *(ASVS V10.2.1)*
- [ ] A callback with a missing, wrong, stale, or replayed transaction-binding value is rejected.
- [ ] Parallel authorization attempts in the same browser session cannot swap callback values across transactions.
- [ ] Transaction-binding values are not logged or exposed through diagnostic output beyond what is necessary for safe operation.
- [ ] Failed binding validation cannot continue to the token exchange or authenticated application session.
