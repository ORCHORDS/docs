# Agent Tokens Usage Telemetry

## Scope

Defines how ORCHORDS agents emit, aggregate, and analyze token usage telemetry so cost, latency, and prompt-size regressions are visible to operators and FinOps.

## Identifier table

| Field | Value |
|---|---|
| Topic | Token usage telemetry for agent invocations |
| Inputs | Provider usage records, agent step logs, model identifier |
| Outputs | Telemetry events, dashboards, anomaly alerts |
| Audience | AI Platform, FinOps, Reliability Engineering |
| Trigger | Every agent invocation and step |
| Companion | AGENT_COST_BUDGET_ENFORCEMENT.md, AGENT_OBSERVABILITY_METRICS.md |

## Plan

1. Emit a structured usage event at the end of every step that consumes tokens, including model identifier, prompt tokens, completion tokens, cached tokens, tool tokens, and step identifier.
2. Tag the event with tenant, agent identifier, task identifier, and revision SHA of the prompt and agent configuration.
3. Forward events to the central telemetry pipeline with a documented schema and documented retention period.
4. Aggregate events into per-tenant, per-agent, and per-model dashboards updated at most every five minutes.
5. Define anomaly alerts for sudden cost increase, sudden prompt-size increase, and a sudden drop in completion tokens that may indicate truncations.
6. Reconcile aggregated events against provider usage detail at least daily to catch missing or duplicated records.
7. Surface the telemetry into the cost budget enforcement path so it can act on observed usage.

## Inputs

- Step-level usage records from the model provider
- Prompt and agent configuration revisions
- Tenant and agent identifier context

## ORCHORDS Profile

| Metric | Definition |
|---|---|
| prompt_tokens | Tokens in the input prompt for the step |
| completion_tokens | Tokens generated by the model |
| cached_tokens | Tokens served from provider cache |
| tool_tokens | Tokens consumed by tool calls and responses |
| step_duration_ms | Wall-clock duration of the step |
| cost_usd_micros | Cost in USD micro-units using the current pricing table |

## Implementation Notes

- Telemetry events use a versioned schema; bump the schema version on any breaking change.
- Include a deduplication identifier so retries do not double-count usage.
- Dashboards and alerts SHOULD run on aggregated, not raw, events to keep cost predictable.
