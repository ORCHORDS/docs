# Bug Report Template

A well-structured bug report is essential for effective software development and quality assurance. This template ensures consistent documentation that helps developers quickly understand and resolve issues.

## Reproduction Steps

Clearly document the exact sequence of actions required to reproduce the bug. Include:
- Browser version and operating system
- Specific user actions taken
- Time frame when issue occurred
- Any prerequisite conditions
- Step-by-step instructions that others can follow

## Expected vs Actual Results

**Expected:** Describe what should happen under normal circumstances.
**Actual:** Detail exactly what occurred instead.
Be specific about the difference between expected and actual behavior.

## Environment Details

Include comprehensive system information:
- Operating system version
- Browser type and version
- Device specifications
- Network conditions
- Any relevant software versions
- Test environment (staging, production, etc.)

## Severity Classification

Rate bug impact on a scale of 1-4:
- **1 (Critical):** System crash, data loss, security vulnerability
- **2 (High):** Major functionality broken,严重影响用户体验
- **3 (Medium):** Minor issues, UI problems, performance degradation
- **4 (Low):** Cosmetic issues, typos, minor annoyances

## Labels and Categories

Apply appropriate tags for organization:
- Feature area (login, payment, dashboard)
- Component affected
- Priority level
- Type of issue (UI, backend, API)
- Status indicators (confirmed, in progress)

## Supporting Media

Attach relevant screenshots or screen recordings showing the bug. Include:
- Before/after comparison images
- Error messages with timestamps
- Video demonstrations of the issue
- Clear visual evidence of problem occurrence

## Logs and Technical Details

Provide technical information:
- Browser console errors
- Server logs
- Database error messages
- API response codes
- Stack traces if applicable
- Memory usage or performance metrics

This standardized approach ensures efficient bug tracking, faster resolution times, and improved collaboration between development and testing teams.
