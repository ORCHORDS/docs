# Argo CD ApplicationSet Controller Version Governance

## 1. Purpose

This reference card governs the lifecycle of the **ApplicationSet** controller — the multi-cluster, multi-tenant GitOps add-on for Argo CD. It applies to platform teams that manage a fleet of clusters or a large population of `Application` resources via a templated, controller-driven model.

## 2. Scope

In scope:

- ApplicationSet ≥ 0.5.x (apiVersion `argoproj.io/v1alpha1`).
- Generators: `list`, `cluster`, `git`, `git-directory`, `matrix`, `merge`, `schema` (Provider).
- Cluster-scoped resources secret `argocd/argocd-image-updater-secret` and per-cluster ServiceAccount tokens.
- Argo CD Notifications (separate controller) for Slack, MS Teams, webhook.

Out of scope:

- The original single-Application controller behaviour (use ApplicationSet for new workloads).
- Argo Rollouts (independent lifecycle).

## 3. Versioning policy

- Pin the ApplicationSet controller image to a specific patch release (e.g. `quay.io/argoproj/argocd-applicationset:v0.5.6`) and digest.
- ApplicationSet controller must match the Argo CD Server/Application Controller version (within the same minor) to avoid API drift.
- Maintain a single ApplicationSet per tenant/fleet; do not duplicate generators across resources.
- Restrict `ApplicationSet.Spec.Generators[*].Git.Template.Spec` to allow-listed repo/path prefixes.

## 4. Compatibility matrix

| ApplicationSet | Argo CD | Kubernetes | Notes |
| --- | --- | --- | --- |
| 0.4.x | 2.10.x | 1.27+ | Matrix generator stable |
| 0.5.x | 2.11.x | 1.28+ | Pull-request generator GA |
| 0.6.x | 2.12.x | 1.30+ | Cluster API integration improvements |

## 5. Generator best practices

- **`list`**: use for fixed fleet configurations (e.g. per-region clusters).
- **`cluster`**: queries the Argo CD cluster registry; pair with a ServiceAccount token refresh schedule.
- **`git`**: only one `path:` per generator when possible to avoid double-renders.
- **`matrix`**: combine `cluster` × `git` to fan out template per cluster and per repo path.
- **`merge`**: use for multi-source Helm values layered across repositories.

## 6. Sync policy

- Default to `automated.selfHeal=true` and `prune=true`.
- Use `automated.allowEmpty=false` to detect a misconfigured template.
- Apply per-namespace `sync.windows` to align with maintenance windows.

## 7. Upgrade procedure

1. Roll the ApplicationSet controller image; verify with `kubectl get applicationsets -A` and `kubectl describe` on each.
2. Upgrade the underlying Argo CD version in lockstep.
3. Validate generator output: `argocd appset list -o yaml | kubectl neat` to compare against a known-good baseline.
4. Promote after 24 h of clean `Sync: Synced` and `Health: Healthy`.

## 8. Rollback procedure

- `kubectl rollout undo deployment/argocd-applicationset-controller` reverts the controller.
- Applications generated by the controller retain their last-rendered state; no data loss.

## 9. Observability

- Required metrics: `applicationset_reconciler_duration_seconds{generator,result}`, `applicationset_resources_count{generator,status}`, `argocd_app_sync_total{phase}`.
- Alert on `applicationset_reconciler_duration_seconds{result="error"}` > 0.05 sustained over 5 minutes.
