# SLSA Build Track Level Adoption

## Level semantics

SLSA v1.2 has separate Build and Source tracks. Build L1 requires provenance that describes how an artifact was produced. Build L2 requires signed provenance generated by a hosted build platform. Build L3 adds hardened-build-platform requirements, including isolation so one build cannot influence another and resistance to user-defined build steps altering provenance. A managed CI label alone proves no level.

The v1.0 provenance predicate type is `https://slsa.dev/provenance/v1`. Its `buildDefinition` contains `buildType`, `externalParameters`, `internalParameters`, and `resolvedDependencies`; `runDetails` contains `builder.id`, `metadata`, and optional `byproducts`. The statement subject must bind output names to cryptographic digests. Policy must compare the subject digest, expected `builder.id`, expected `buildType`, and allowed external parameters rather than merely parsing the envelope.

```json
{"_type":"https://in-toto.io/Statement/v1","subject":[{"name":"app","digest":{"sha256":"..."}}],"predicateType":"https://slsa.dev/provenance/v1","predicate":{"buildDefinition":{"buildType":"https://example.com/build/v1","externalParameters":{"ref":"refs/tags/v2.4.0"},"resolvedDependencies":[{"uri":"git+https://example/repo@sha1:...","digest":{"sha1":"..."}}]},"runDetails":{"builder":{"id":"https://ci.example/builders/release@v3"}}}}
```

## Assessment and enforcement

Inventory each release path, including manual rebuilds and hotfixes. For L2, demonstrate that the platform—not a user-supplied post-build step—signs provenance. For L3, document tenant isolation, ephemeral worker lifecycle, secret boundaries, administrator access, and how provenance fields are protected from build-controlled substitution. Keep an evidence matrix keyed to the exact v1.2 requirement IDs.

Verify offline against a captured statement, signature/bundle, trust root, and policy. Negative tests change the subject digest, builder ID, source revision, build type, and one external parameter. Record verifier version and output. Introduce enforcement in report mode, then block at publication or deployment. Roll back the gate without deleting failed provenance; publish a time-limited exception for exact digests. Metrics should distinguish missing provenance, invalid signature, untrusted builder, and parameter-policy mismatch.
