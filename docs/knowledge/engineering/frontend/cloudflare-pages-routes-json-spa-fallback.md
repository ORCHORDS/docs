# Cloudflare Pages `_routes.json` SPA Fallback Optimisation

Date: 2026-08-23
Author: example.com
Status: production

---

## Symptom / Use-case

Your single-page application deployed on Cloudflare Pages hits a `404` on deep-link navigation, or your Pages Functions are invoked on every static asset request — slowing down image/CSS/JS delivery by running unnecessary Worker code. By authoring a `_routes.json` file you explicitly control which URL patterns invoke Functions (and therefore the SPA fallback) vs. which are served directly from the static asset CDN, reducing function invocations and improving TTFB for all non-HTML requests.

---

## Context

Cloudflare Pages serves files from a static asset store (backed by Cloudflare's global CDN) and optionally routes requests through Pages Functions (Workers). Without `_routes.json`:

- If you have **no** `functions/` directory: all requests serve static assets; a missing path returns 404.
- If you have **any** `functions/` directory: Pages auto-generates a `_routes.json` that excludes common asset paths (`/assets/*`, `/*.png`, etc.) but the heuristic may miss custom paths.

`_routes.json` lets you precisely declare which paths should invoke Functions (`include`) and which should bypass them (`exclude`). The SPA fallback pattern — serving `index.html` for all unknown paths — requires a catch-all Function combined with targeted exclusions so that JS/CSS/image assets are never routed through the Function layer.

---

## Basic `_routes.json` Structure

```json
{
  "version": 1,
  "include": ["/*"],
  "exclude": [
    "/assets/*",
    "/*.js",
    "/*.css",
    "/*.png",
    "/*.jpg",
    "/*.jpeg",
    "/*.webp",
    "/*.avif",
    "/*.svg",
    "/*.ico",
    "/*.woff2",
    "/*.woff",
    "/*.ttf",
    "/*.map"
  ]
}
```

Place this file at the **root of your build output** (e.g. `dist/_routes.json` for Vite projects).

Copy `_routes.json` into `public/` so Vite includes it in the build output automatically:

```bash

  _routes.json

```

## The SPA Fallback Function

```typescript
// functions/[[path]].ts
// Matches all paths not excluded by _routes.json

export const onRequest: PagesFunction<Env> = async (ctx) => {
  // Serve index.html for every unmatched path (client-side router handles it)
  const indexUrl = new URL("/index.html", ctx.request.url);
  return ctx.env.ASSETS.fetch(new Request(indexUrl.toString(), ctx.request));
};
```

The catch-all `[[path]]` parameter matches zero or more path segments. Because `_routes.json` excludes asset patterns, this function is only invoked for HTML navigation requests.

## Generated `_routes.json` via Vite Plugin

For projects with a hashed asset manifest, generate `_routes.json` dynamically to match actual output files:

```typescript
// vite-plugin-cloudflare-routes.ts

import type { Plugin } from "vite";
import fs from "fs";
import path from "path";

export function cloudflareRoutes(): Plugin {
  return {
    name: "cloudflare-routes",
    closeBundle() {
      const outDir = this.environment?.options?.build?.outDir ?? "dist";
      const assetsDir = path.join(outDir, "assets");

      const assetExcludes = fs.existsSync(assetsDir)
        ? fs
            .readdirSync(assetsDir)
            .map((f) => `/assets/${f}`)
        : ["/assets/*"];

      const routes = {
        version: 1,
        include: ["/*"],
        exclude: [
          "/assets/*",
          "/*.js",
          "/*.css",
          "/*.png",
          "/*.jpg",
          "/*.jpeg",
          "/*.webp",
          "/*.avif",
          "/*.svg",
          "/*.ico",
          "/*.woff2",
          "/*.woff",
          "/*.ttf",
          "/*.map",
        ],
      };

      fs.writeFileSync(
        path.join(outDir, "_routes.json"),
        JSON.stringify(routes, null, 2)
      );
    },
  };
}
```

```typescript
// vite.config.ts
import { defineConfig } from "vite";
import react from "@vitejs/plugin-react";
import { cloudflareRoutes } from "./vite-plugin-cloudflare-routes";

export default defineConfig({
  plugins: [react(), cloudflareRoutes()],
  build: { outDir: "dist" },
});
```

## API Routes Alongside SPA Fallback

When your Pages Functions include an API, add the API prefix to the `include` list and keep the rest excluded:

```json
{
  "version": 1,
  "include": ["/*"],
  "exclude": [
    "/assets/*",
    "/*.js",
    "/*.css",
    "/*.png",
    "/*.jpg",
    "/*.jpeg",
    "/*.webp",
    "/*.avif",
    "/*.svg",
    "/*.ico",
    "/*.woff2",
    "/*.woff",
    "/*.ttf",
    "/*.map"
  ]
}
```

API functions under `functions/api/` are auto-included because they are not listed in `exclude`. The `include: ["/*"]` with selective `exclude` is the correct pattern — not an `include` list of specific API paths, which would require maintenance every time a new endpoint is added.

## Diagnosing Invocation Counts

Use the Pages deployment dashboard → **Functions** tab → **Invocations** to verify that static assets are not triggering function invocations. Expected result: invocations should roughly equal HTML page views, not total requests.

From the CLI:

```bash
# Preview with wrangler to test routing locally
wrangler pages dev dist --compatibility-date=2024-09-23

# Confirm a JS file is served directly (no Worker log output)
curl -I http://localhost:8788/assets/index-abc123.js
# Should NOT show any function execution in wrangler output

# Confirm a deep link falls through to index.html
curl -I http://localhost:8788/dashboard/settings
# Should show Worker execution + 200 with Content-Type: text/html
```

## Anti-patterns

- **No `_routes.json` with a catch-all function**: Every request — including images, fonts, and JS chunks — runs through your Worker. This wastes function invocation quota and adds latency to asset delivery.
- **`include` list of only specific paths**: This requires updating the list whenever a new route is added. The `include: ["/*"]` + `exclude` pattern is far more maintainable.
- **Excluding `/api/*` in `_routes.json`**: Your API functions must NOT be in the `exclude` list or they will never be invoked and will return 404 from the static store instead.
- **Placing `_routes.json` in `public/` for a non-Vite project**: Make sure your framework copies `public/` contents to the build output root. Check with `ls dist/` after building.
- **Version field missing or wrong**: `_routes.json` requires `"version": 1`. An invalid file silently falls back to auto-generated rules — verify by checking Pages build logs for a `_routes.json` parse warning.

---

## Gotchas

- `exclude` rules take priority over `include` rules. If a path matches both, it is excluded (not routed through a Function).
- The maximum number of combined `include` + `exclude` rules is **100**. Per-file exclusions from the generated manifest will hit this limit on large projects — use glob patterns instead.
- `wrangler pages dev` respects `_routes.json` in local mode but may not perfectly replicate production edge routing for complex patterns. Always verify after deployment.
- Static assets on Pages are served with long `Cache-Control: max-age=31536000, immutable` headers automatically. If you accidentally route an asset through a Function, the response headers from `env.ASSETS.fetch()` preserve this, but the extra hop still adds latency.
- Trailing-slash normalisation differs between the static CDN and the Function layer. The SPA fallback function will receive `/about/` as-is; ensure your client router handles both `/about` and `/about/`.

## Verification

```bash
# Build and deploy
npm run build
wrangler pages deploy dist --project-name my-spa

# Verify _routes.json was published
curl https://my-spa.pages.dev/_routes.json
# => {"version":1,"include":["/*"],"exclude":["/assets/*", ...]}

# Check a static asset bypasses the function (fast response, CDN headers)
curl -sI https://my-spa.pages.dev/assets/index-abc123.js | grep -E "cf-cache-status|content-type"
# => cf-cache-status: HIT
# => content-type: application/javascript

# Check a deep link serves index.html
curl -sI https://my-spa.pages.dev/dashboard/settings | grep content-type
# => content-type: text/html; charset=utf-8
```
