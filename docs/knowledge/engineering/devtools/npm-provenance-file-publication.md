# npm provenance-file publication contract

**Problem**

Publishing provenance from a supplied bundle decouples attestation generation from npm publish and can bind the wrong artifact or workflow identity.

**Date:** 2026-08-18
**Author:** ORCHORDS
**Status:** documented

## When to use

Use only when the provenance bundle is generated by an approved external attestation flow.

## Controls

- Bind bundle subject digests to the exact package tarball.
- Protect the bundle as release evidence, not a reusable credential.
- Keep registry and package identity checks.

## Implementation

- Generate package with `npm pack`, hash it, validate the bundle, then publish with explicit provenance file.
- Record workflow SHA and package version.
- Delete transient copies.

## Tests

- Test wrong subject, package/version, registry, tampering, replay, and missing bundle.

## Gotchas

- A valid bundle for another tarball is not valid here.
- Feature support is npm/registry-version dependent.
- Provenance does not scan package content.
