# Biome Linter and Formatter Setup for Cloudflare Workers Projects

Date: 2026-08-24
Author: example.com
Status: production

---

## Symptom / Use-case

A Workers project uses ESLint + Prettier but the dual-tool setup causes:
- Conflicting rule interpretations between lint and format passes
- Slow CI pipelines (two separate tool invocations)
- Complex `.eslintrc` + `.prettierrc` maintenance burden
- False positives from DOM/browser-specific lint rules that do not exist in the Workers runtime

The team wants a single, fast, zero-config-friendly toolchain that understands TypeScript and can be enforced in CI and pre-commit hooks.

---

## Context

Biome is a Rust-based linter and formatter that replaces ESLint and Prettier in one binary. It ships with sensible defaults, supports TypeScript natively, and runs orders of magnitude faster than the Node.js equivalents. For Cloudflare Workers specifically:

- The Workers runtime exposes a subset of the Web Platform APIs — no `document`, `window`, or DOM types.
- Import ordering matters for bundle size when using esbuild (Wrangler's default bundler).
- Biome's rule set can be scoped to exclude browser-only globals that would never appear in a Worker.

Biome version targeted: **1.8+**. Wrangler version targeted: **3.x**.

---

## Solution

### 1. Install Biome

```bash
npm install --save-dev --save-exact @biomejs/biome
npx @biomejs/biome init
```

`--save-exact` pins the version so every developer and CI run uses the identical binary.

### 2. biome.json — Workers-optimised configuration

```json
{
  "$schema": "https://biomejs.dev/schemas/1.8.0/schema.json",
  "organizeImports": {
    "enabled": true
  },
  "linter": {
    "enabled": true,
    "rules": {
      "recommended": true,
      "correctness": {
        "noUnusedVariables": "error",
        "noUnusedImports": "error",
        "useExhaustiveDependencies": "off"
      },
      "suspicious": {
        "noExplicitAny": "warn",
        "noConsoleLog": "off"
      },
      "style": {
        "noNonNullAssertion": "warn",
        "useConst": "error",
        "useImportType": "error"
      },
      "complexity": {
        "noBannedTypes": "error",
        "noForEach": "off"
      }
    }
  },
  "formatter": {
    "enabled": true,
    "indentStyle": "tab",
    "indentWidth": 2,
    "lineWidth": 100
  },
  "javascript": {
    "formatter": {
      "quoteStyle": "double",
      "trailingCommas": "all",
      "semicolons": "always"
    },
    "globals": [
      "Request",
      "Response",
      "Headers",
      "URL",
      "URLSearchParams",
      "fetch",
      "caches",
      "crypto",
      "ReadableStream",
      "WritableStream",
      "TransformStream",
      "TextEncoder",
      "TextDecoder",
      "addEventListener",
      "self"
    ]
  },
  "files": {
    "ignore": [
      ".wrangler/**",
      "dist/**",
      "node_modules/**",
      "worker-configuration.d.ts"
    ]
  }
}
```

Key decisions:
- `indentStyle: "tab"` — matches Wrangler scaffold defaults and is more accessible.
- `useImportType: "error"` — enforces `import type` for type-only imports, which esbuild strips cleanly.
- `globals` lists Workers-runtime globals so Biome does not flag them as undefined.
- `worker-configuration.d.ts` is generated by `wrangler types` and must not be reformatted.

### 3. package.json scripts

```json
{
  "scripts": {
    "lint": "biome lint --error-on-warnings ./src",
    "lint:fix": "biome lint --write ./src",
    "format": "biome format ./src",
    "format:fix": "biome format --write ./src",
    "check": "biome check ./src",
    "check:fix": "biome check --write ./src"
  }
}
```

`biome check` runs lint + format + import organisation in one pass. Use `check:fix` locally; use `check` (no `--write`) in CI.

### 4. TypeScript Worker entry point — clean Biome output

```typescript
// src/index.ts
import type { Env } from "./types";
import { handleRequest } from "./handler";

export default {
    async fetch(request: Request, env: Env, ctx: ExecutionContext): Promise<Response> {
        return handleRequest(request, env, ctx);
    },
} satisfies ExportedHandler<Env>;
```

```typescript
// src/types.ts
export interface Env {
    API_KEY: string;
    MY_KV: KVNamespace;
    MY_BUCKET: R2Bucket;
}
```

### 5. CI — GitHub Actions lint/format check

```yaml
# .github/workflows/lint.yml
name: Lint & Format

on:
  pull_request:
  push:
    branches: [main]

jobs:
  biome:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4

      - uses: actions/setup-node@v4
        with:
          node-version: 22
          cache: npm

      - run: npm ci

      - name: Biome check (no auto-fix)
        run: npx @biomejs/biome ci ./src
```

`biome ci` is identical to `biome check` but exits non-zero on any warning, making it suitable for strict CI gating.

### 6. Pre-commit hook via lint-staged

```bash
npm install --save-dev lint-staged husky
npx husky init
```

```json
// package.json (addition)
{
  "lint-staged": {
    "*.{ts,tsx,js,jsx,json}": [
      "biome check --write --no-errors-on-unmatched"
    ]
  }
}
```

```bash
# .husky/pre-commit
npx lint-staged
```

This applies Biome fixes only to staged files, keeping the pre-commit hook fast even in large monorepos.

## Implementation Details

### Rule customisation for Workers runtime

The Workers runtime does not expose:
- `document`, `window`, `navigator`, `location` (DOM globals)
- `process`, `Buffer`, `__dirname`, `__filename` (Node.js globals)

Biome's `javascript.globals` array declares *additional* valid globals. Biome itself does not have a DOM preset in the same sense as ESLint, but the `noUndeclaredVariables` rule (off by default in recommended) will flag unknown globals if enabled. For Workers, enable it and populate `globals` carefully:

```json
{
  "linter": {
    "rules": {
      "correctness": {
        "noUndeclaredVariables": "error"
      }
    }
  }
}
```

### Import sorting

Biome's import organiser sorts imports into groups:
1. Side-effect imports (`import "./side-effect"`)
2. Node built-ins (none in Workers unless using the `node:` compat layer)
3. External packages
4. Internal (`./`, `../`)

To trigger a sort, run `biome check --write` or the VS Code extension save action.

### Migrating from ESLint + Prettier

```bash
# 1. Remove old tooling
npm uninstall eslint prettier eslint-config-prettier \
  @typescript-eslint/eslint-plugin @typescript-eslint/parser

# 2. Remove config files
rm -f .eslintrc* .eslintignore .prettierrc* .prettierignore

# 3. Run Biome migration helper (experimental)
npx @biomejs/biome migrate eslint --write
npx @biomejs/biome migrate prettier --write

# 4. Review biome.json and adjust
# 5. Run check to see baseline violations
npx @biomejs/biome check ./src
```

The migration commands translate known ESLint rules to their Biome equivalents and insert them into `biome.json`.

## Anti-patterns

- **Running `biome format --write` in CI.** CI should only check, never auto-commit. Use `biome ci` or `biome check` without `--write`.
- **Omitting `worker-configuration.d.ts` from the ignore list.** Biome will reformat the generated file on every run, creating spurious diffs.
- **Using `noConsoleLog: "error"` in Workers.** `console.log` in Workers emits structured logs visible in `wrangler tail`. Suppressing it blocks a primary observability tool.
- **Mixing tabs and spaces after migration.** If pre-existing files used spaces, run `biome format --write ./src` once before the first CI run to normalise everything.

---

## Gotchas

- Biome does not yet support `.vue`, `.svelte`, or template literal CSS. If your Worker serves an HTML template string, Biome formats the TypeScript wrapper but not the inline HTML.
- The `useImportType` rule requires TypeScript 5+ and `"isolatedModules": true` (which Wrangler sets by default) to be fully effective.
- `biome ci` reads the closest `biome.json`. In a monorepo, ensure each Worker package has its own `biome.json` or the root config covers it via `"files": { "include" }`.
- Biome's VSCode extension (`biomejs.biome`) must be set as the default formatter for `.ts` files, otherwise Prettier (if still installed as a transitive dep) may intercept saves.

## Verification

```bash
# Confirm Biome version
npx @biomejs/biome --version

# Dry-run check — shows violations without modifying files
npx @biomejs/biome check ./src

# Confirm CI command exits 0 on clean code
npx @biomejs/biome ci ./src
echo $?  # should be 0

# Verify import sorting is applied
npx @biomejs/biome check --write ./src/index.ts
git diff ./src/index.ts  # review changes
```
