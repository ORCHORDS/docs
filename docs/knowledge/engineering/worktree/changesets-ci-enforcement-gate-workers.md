# Changesets CI Enforcement Gate for Workers

- **Date**: 2026-08-23
- **Author**: example.com
- **Status**: production

## Symptom / Use-case
A Cloudflare Workers monorepo uses `@changesets/cli` to manage versioning and changelogs, but engineers frequently forget to add a changeset file when their PR modifies a publishable package. The omission is caught only at release time when `changeset version` produces no bump for a changed package, or worse — the package ships with no CHANGELOG entry. A CI enforcement gate that blocks merging unless a changeset is present (or the PR is explicitly exempted) prevents this class of release regression.

## Context
Changesets work by requiring contributors to commit a small YAML-ish file under `.changeset/` (e.g. `.changeset/happy-turtles.md`) that declares which packages are changed and the severity (major / minor / patch). The `changeset status` command exits non-zero if no changeset covers any changed publishable package. Combining `changeset status --since=origin/main` with GitHub Actions — and an escape hatch label for "no release needed" PRs — creates a lightweight, enforceable gate without changing the developer workflow.

## Changeset file anatomy

```markdown
<!-- .changeset/happy-turtles.md — generated by `pnpm changeset` -->
---
"@example-org/example-repo": minor
"@example-org/example-repo": patch
---

Add request batching to ApiClient and fix TypeScript generics in SharedTypes.
```

```bash
# Add a changeset interactively
pnpm changeset

# Add a changeset non-interactively (useful in scripts)
pnpm changeset add --empty    # creates an empty changeset (patch, no release)

# Check status: exits 0 if changesets exist for changed packages
pnpm changeset status --since=origin/main

# Preview what the next version will be
pnpm changeset status --verbose --since=origin/main
```

## GitHub Actions enforcement workflow

```yaml
# .github/workflows/require-changeset.yml
name: Require Changeset

on:
  pull_request:
    types: [opened, synchronize, labeled, unlabeled]
    branches: [main]

jobs:
  changeset-check:
    name: Changeset Required
    runs-on: ubuntu-latest
    # Skip if the PR carries the "no-release" exemption label
    if: |
      !contains(github.event.pull_request.labels.*.name, 'no-release') &&
      !contains(github.event.pull_request.labels.*.name, 'ci-only')

    steps:
      - uses: actions/checkout@v4
        with:
          fetch-depth: 0    # full history so --since can diff against origin/main

      - uses: pnpm/action-setup@v3
        with:
          version: 9

      - uses: actions/setup-node@v4
        with:
          node-version: 22
          cache: pnpm

      - name: Install dependencies
        run: pnpm install --frozen-lockfile

      - name: Check for changeset
        run: |
          set +e
          OUTPUT=$(pnpm changeset status --since=origin/main 2>&1)
          EXIT_CODE=$?
          echo "$OUTPUT"
          set -e

          if [ $EXIT_CODE -ne 0 ]; then
            echo ""
            echo "::error::No changeset found for changed packages."
            echo "::error::Run 'pnpm changeset' locally, commit the .changeset/*.md file, and push."
            echo "::error::If no release is intended, add the 'no-release' label to this PR."
            exit 1
          fi
```

## Exemption labels: no-release and ci-only

```yaml
# .github/workflows/require-changeset.yml (label-gate approach)
# Job above skips on no-release or ci-only.
# This companion job runs only on labeled PRs to add a status check:
  changeset-exempt:
    name: Changeset Required
    runs-on: ubuntu-latest
    if: |
      contains(github.event.pull_request.labels.*.name, 'no-release') ||
      contains(github.event.pull_request.labels.*.name, 'ci-only')
    steps:
      - name: Exempt from changeset requirement
        run: echo "PR is labeled no-release or ci-only — changeset not required."
```

```bash
# Create the labels via GitHub CLI (run once per repository)
gh label create "no-release" \
  --description "PR does not need a changeset (docs, CI, chores)" \
  --color "e4e669"

gh label create "ci-only" \
  --description "PR only changes CI/CD configuration" \
  --color "bfd4f2"
```

## TypeScript: validate changeset files in a pre-push hook

```typescript
// scripts/check-changeset.ts
import { execSync } from "node:child_process";
import { readdirSync } from "node:fs";
import { join } from "node:path";

const CHANGESET_DIR = ".changeset";
const EXEMPT_FILES = new Set(["README.md", "config.json"]);

function hasChangeset(): boolean {
  const files = readdirSync(CHANGESET_DIR).filter(
    (f) => !EXEMPT_FILES.has(f) && f.endsWith(".md")
  );
  return files.length > 0;
}

function diffedPublishablePackages(base = "origin/main"): string[] {
  const diff = execSync(
    `git diff --name-only ${base}...HEAD`,
    { encoding: "utf8" }
  );
  const changed = diff.split("\n").filter(Boolean);
  // Only flag packages/* and workers/* that have a package.json
  return [
    ...new Set(
      changed
        .filter((f) => f.startsWith("packages/") || f.startsWith("workers/"))
        .map((f) => f.split("/").slice(0, 2).join("/"))
    ),
  ];
}

const changed = diffedPublishablePackages();
if (changed.length > 0 && !hasChangeset()) {
  console.error("Changed publishable packages:", changed);
  console.error(
    "Run `pnpm changeset` to add a changeset, then commit the result."
  );
  process.exit(1);
}
console.log("Changeset check passed.");
```

```yaml
# lefthook.yml — run the check before pushing
pre-push:
  commands:
    check-changeset:
      glob: 'packages/**/*.ts workers/**/*.ts'
      run: npx tsx scripts/check-changeset.ts
```

## Release workflow: consuming enforced changesets

```yaml
# .github/workflows/release.yml
name: Release

on:
  push:
    branches: [main]

jobs:
  release:
    name: Release
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
        with:
          fetch-depth: 0
          token: ${{ secrets.RELEASE_BOT_TOKEN }}

      - uses: pnpm/action-setup@v3
        with:
          version: 9

      - uses: actions/setup-node@v4
        with:
          node-version: 22
          cache: pnpm
          registry-url: https://registry.npmjs.org

      - run: pnpm install --frozen-lockfile

      # Creates a "Version Packages" PR, or merges it if changesets are present
      - name: Create Release PR or Publish
        uses: changesets/action@v1
        with:
          publish: pnpm run release
          version: pnpm run version
          commit: "chore: version packages"
          title: "chore: version packages"
        env:
          GITHUB_TOKEN: ${{ secrets.GITHUB_TOKEN }}
          NPM_TOKEN: ${{ secrets.NPM_TOKEN }}
```

```jsonc
// package.json scripts
{
  "scripts": {
    "version": "changeset version && pnpm install --no-frozen-lockfile",
    "release": "changeset publish"
  }
}
```

## Detecting changesets for private (non-published) Workers

Cloudflare Worker packages are typically `"private": true` and not published to npm. Changesets can still track their changelog entries even for private packages:

```jsonc
// .changeset/config.json
{
  "$schema": "https://unpkg.com/@changesets/config@3.0.0/schema.json",
  "changelog": "@changesets/cli/changelog",
  "commit": false,
  "linked": [],
  "access": "restricted",
  "baseBranch": "main",
  "updateInternalDependencies": "patch",
  "ignore": [],
  "privatePackages": {
    "version": true,
    "tag": true
  }
}
```

## Anti-patterns
- Running `changeset status` without `--since=origin/main` — it checks all packages against the last published version, producing false positives on packages that were never changed in this PR.
- Skipping the enforcement job for draft PRs and forgetting to re-enable it before merge — add `ready_for_review` to the workflow triggers.
- Using the `changeset-bot` GitHub App as the sole enforcement mechanism — it only comments, it never blocks merge; the CI status check is the real gate.
- Adding `"ignore"` entries in `.changeset/config.json` for packages that are actually publishable — silent misses on real changes.
- Committing `.changeset/*.md` files in the release PR back to `main` without deleting them — changesets are consumed on `changeset version` and must be removed; the `changesets/action` does this automatically.

## Gotchas
- `pnpm changeset status --since=origin/main` exits 0 even when there are no changed packages AND no changeset files — it only fails when changed packages exist but have no covering changeset.
- The `changesets/action` requires a `GITHUB_TOKEN` with write permissions to create the "Version Packages" PR; the default `GITHUB_TOKEN` in Actions is sufficient unless branch protection rules block bot commits.
- Renaming a package in `package.json` without updating `.changeset/config.json` will cause `changeset version` to fail silently — the old package name is not found, the changeset is orphaned.
- `"privatePackages": { "version": true }` in config requires `@changesets/cli >= 2.26.0`; earlier versions ignore the field and skip private packages entirely.
- In a turborepo setup, `turbo run release` may not respect the changeset topological order; call `pnpm -r run release` or use the `changesets/action` publish command directly.

## Verification
```bash
# Verify changeset status for current PR branch
git fetch origin main
pnpm changeset status --since=origin/main --verbose

# Simulate what the CI check runs
pnpm changeset status --since=origin/main; echo "Exit: $?"

# List all pending changesets
ls .changeset/*.md | grep -v README | grep -v config

# Preview next version bumps
pnpm changeset version --dry-run 2>/dev/null || \
  pnpm changeset status --verbose --since=origin/main
```
