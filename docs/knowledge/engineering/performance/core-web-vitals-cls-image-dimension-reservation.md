# Core Web Vitals CLS Image Dimension Reservation

## Scope
This article addresses the Cumulative Layout Shift (CLS) component of Core Web Vitals as it relates to image dimension reservation—the practice of declaring an image's intrinsic width and height so the browser can reserve layout space before the image loads. The scope covers the Layout Shift API, the `width`/`height` HTML attributes, CSS `aspect-ratio`, the `srcset`/`sizes` responsive attributes, and the LCP interaction where an unreserved image causes the largest contentful paint element to shift after load. The article is restricted to client-side image rendering; it does not cover video, SVG, or canvas-based content. It is concerned with the engineering patterns that eliminate image-driven CLS, the failure modes that arise when those patterns are not followed, and the measurement signals that distinguish a fix from a placebo.

## Workflow or implementation guidance
Begin by adopting the `width` and `height` HTML attributes on every `<img>` element. The browser uses these attributes to compute the image's intrinsic aspect ratio and reserve layout space before the image's bytes arrive. This is the single highest-leverage CLS fix: it requires no JavaScript, no CSS, and no build pipeline. Modern browsers honour the attributes even when the image is responsive (scaled by CSS or `srcset`); the ratio, not the absolute dimensions, is what matters. Audit the codebase for `<img>` elements missing one or both attributes, and add them at the source rather than via JavaScript injection.

For images whose aspect ratio is unknown at build time (user-uploaded content, dynamically generated thumbnails), use CSS `aspect-ratio` to declare a target ratio. The browser reserves space based on the ratio and the parent's width, so a 16:9 image in a 600-px-wide column reserves 338 px of height. Combine `aspect-ratio` with `object-fit: cover` to crop the image to fill the reserved space without distorting it. Where the aspect ratio varies per image, query the image's metadata (EXIF, image processing pipeline output) and inject the ratio as an inline style or attribute.

For responsive images, declare `srcset` and `sizes` correctly. The `sizes` attribute tells the browser which image source from the `srcset` to download based on the rendered size; an incorrect `sizes` value causes the browser to download a too-large or too-small image, and in the worst case the downloaded image renders at a different aspect ratio than the reserved space. Test the `srcset`/`sizes` pair at common viewport widths (320, 768, 1024, 1440, 1920) and confirm the chosen source's aspect ratio matches the reserved ratio.

Avoid loading images via `background-image` for LCP candidates. Background images do not participate in the intrinsic sizing model; the browser cannot reserve space for them without explicit CSS, and the rendered size depends on the `background-size` value. If the image is the LCP candidate, use `<img>` with dimensions; reserve a `<div>` with explicit dimensions if the image must be a background.

For images loaded via JavaScript (lazy-loaded images, dynamically inserted galleries), reserve the space before the script runs. A common failure mode is a JavaScript-driven image insertion that measures the parent container after layout, calculates the image's size, and then inserts the image—causing a one-frame shift. Reserve the space with a placeholder `<div>` whose dimensions are known, then swap the placeholder for the `<img>` once loaded.

For images whose dimensions change after load (a skeleton placeholder swapped for the real image), match the placeholders' aspect ratio to the real image's. A 1:1 skeleton swapped for a 16:9 image is a guaranteed CLS event. Use the same ratio for both, and fade the swap so the user does not perceive the change as a layout shift even if a sub-pixel difference remains.

Avoid the temptation to set `width: 100%; height: auto` and rely on the browser to figure out the ratio. This pattern requires the image's bytes to be parsed before the ratio is known, which means no space is reserved until the image is downloaded. The intrinsic ratio declaration (`width` + `height` attributes, or CSS `aspect-ratio`) is what makes the reservation work.

## Controls
Define three categories of control. The first is a **build-time audit**: a script that scans the HTML or the built bundle for `<img>` elements without `width` and `height` attributes, and fails the build if any are found. The second is a **CSS audit**: a script that flags `aspect-ratio` declarations that do not match the corresponding image's known ratio (from the build pipeline's image manifest). The third is a **CLS regression alert**: a real-user monitoring pipeline that buckets sessions by page template and alerts when the p75 CLS for a template exceeds 0.1.

A useful guardrail metric is the **layout shift attribution**: for each CLS event captured by the Performance Observer, identify the moved element and its source. If most CLS events trace to images, the image reservation patterns are incomplete; if most trace to web fonts, the fix is different (`font-display: optional`, `size-adjust`).

## Validation evidence
The validation evidence is a side-by-side comparison of CLS distributions before and after the dimension reservation fix, measured via the Performance Observer's `layout-shift` entries. The expected outcome is a substantial reduction in the per-session CLS sum, often from 0.15–0.30 down to under 0.05 for image-heavy pages. Confirm via WebPageTest's "filmstrip" view that no element moves after the initial render. Lighthouse's "Cumulative Layout Shift" audit should report a score of 0.1 or better. Document the per-template CLS distribution, the number of `<img>` elements audited, and the number of templates that lacked dimension reservation.

## Failure modes and correction
**Image loads with a different aspect ratio than reserved**: the `srcset` source chosen by the browser does not match the declared ratio, and the image stretches or letterboxes. Correction: audit the `srcset` URLs and verify each one has the same aspect ratio as the reserved space; generate variants from a single source image with a consistent crop. **Skeleton placeholder swaps cause shift**: the placeholder has a different aspect ratio than the real image. Correction: derive the placeholders' aspect ratio from the real image's metadata, and inject both with the same ratio. **Lazy-loaded images shift the page on entry**: a JavaScript-driven image insertion reserves no space, and the image's height pushes surrounding content down. Correction: reserve the space with a `<div>` whose dimensions match the image's known ratio before the script runs. **Web fonts load and shift text**: an unreserved font causes text to reflow when it loads, which the image's reserved space cannot prevent. Correction: pair image dimension reservation with `font-display: optional` and `size-adjust` to eliminate the font-driven shift. **CLS is low but LCP regresses**: dimension reservation prevents the shift but the image now renders at a smaller size to fit the reserved space. Correction: use `srcset` to deliver a larger image at the same ratio, or reconsider whether the reserved ratio is correct for the design.

## Limitations
The article covers only images, not other CLS sources (web fonts, embeds, dynamic ads). The recommendations assume modern browsers (Chrome 88+, Firefox 89+, Safari 15+) that honour the intrinsic ratio from `width`/`height` attributes; older browsers require CSS-based workarounds. The article assumes the image dimensions are known at build time; for genuinely unknown dimensions, the design must accommodate the variability. The article does not cover the LCP subcomponent of CLS, where the LCP element itself is the moved element; that requires a different set of patterns around the LCP candidate's intrinsic dimensions. The article also does not cover the `content-visibility` CSS property, which can prevent off-screen images from contributing to CLS at all.
