# Recovery Dependency Mapping

## Purpose

Make recovery plans realistic by identifying dependencies that must recover before or alongside a critical capability.

## Requirements

Material recovery planning SHOULD identify upstream/downstream services, identity, data stores, communication channels, suppliers, key personnel/roles, credentials or recovery mechanisms, and assumptions about external availability.

Dependency maps should be reviewed after major architecture, supplier, ownership, or business-impact changes.

Public documentation defines the governance expectation only; detailed dependency maps normally remain private.
