# Project Dependency Management

## Purpose

Make external and cross-team dependencies visible before they silently become schedule or outcome assumptions.

## Requirements

Material dependencies SHOULD identify provider/owner, required outcome, needed-by condition, confidence, constraints, fallback/mitigation, and escalation trigger.

Dependencies with uncertain timing or control should not be represented as committed merely because the project plan assumes them.

See [Dependency Review SOP](../sop/PROJECT_DEPENDENCY_REVIEW_SOP.md).
