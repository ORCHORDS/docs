# Sensitive Support Actions

## Purpose

Apply stronger controls to support actions that can materially affect identity, access, money, privacy, security, or irreversible account state.

## Requirements

Sensitive actions SHOULD require stronger identity verification, least-privilege tooling, explicit reason, attributable logging, and escalation or secondary review when risk justifies it.

Examples include recovery-method changes, security-setting changes, bulk sensitive-data disclosure, privileged account changes, payment-related changes, and destructive actions.

See [Sensitive Support Action SOP](../sop/SENSITIVE_SUPPORT_ACTION_SOP.md).
