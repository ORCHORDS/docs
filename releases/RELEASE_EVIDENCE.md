# Release Evidence

## Purpose

Define the records needed to support a material release decision and later investigation.

## Evidence set

Depending on risk, release evidence SHOULD identify source revision, build or artifact identity, approvals, test results, security and quality checks, known exceptions, migration evidence, signing or integrity records, rollback plan, release time, and post-release verification.

## Retention

Evidence retention should support troubleshooting, security investigation, contractual obligations, and reproducibility needs without retaining sensitive data indefinitely.

## Public boundary

Public release notes may summarize outcomes, but private build identifiers, credentials, internal paths, and sensitive vulnerability details do not belong in this repository.
