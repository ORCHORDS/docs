# Accessibility Policy

## Purpose

ORCHORDS aims to make public digital content usable by people with diverse
abilities, devices, and assistive technologies.

## Standard

Public web content and documentation SHOULD conform to WCAG 2.2 Level AA where
applicable. Conformance claims must be based on evidence; this policy does not
itself assert conformance.

## Requirements

- Keyboard access must not depend on a pointing device.
- Focus order and visible focus must support task completion.
- Text and interactive controls must have sufficient contrast.
- Forms must provide programmatically associated labels and useful errors.
- Images that convey meaning must have appropriate alternative text.
- Captions or equivalent alternatives should be provided for meaningful
  prerecorded audiovisual content.
- Motion and animation should respect user preferences and avoid unnecessary
  seizure or vestibular risk.
- Headings, landmarks, names, roles, and states should be semantically
  meaningful.
- Documentation must use descriptive links, simple tables, and logical heading
  order.

## Verification

Accessibility review combines:

1. automated checks;
2. keyboard-only testing;
3. targeted screen-reader testing for critical journeys;
4. manual review of contrast, semantics, focus, errors, and zoom/reflow;
5. regression review after material UI or content changes.

Automated tools are evidence, not proof of conformance.

## Defects

Accessibility defects are prioritized by user impact, frequency, and whether a
workaround exists. Critical barriers to essential tasks receive the same
escalation discipline as other severe quality defects.
