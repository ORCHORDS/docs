# Web Push API in Next.js with Cloudflare Workers Backend (VAPID Keys)

- **Date**: 2026-08-22
- **Author**: example.com
- **Status**: active

## Symptom / Use-case

You want to send push notifications to users on mobile and desktop from a Next.js application
whose backend runs on Cloudflare Workers. The push flow requires:
1. Generating VAPID key pairs (once, stored as Worker secrets)
2. Subscribing users in the browser and storing `PushSubscription` objects
3. Sending pushes from a Worker using the Web Push Protocol (RFC 8030)

The challenge: Workers lack Node.js's `web-push` npm package (it uses Node crypto APIs
unavailable in the Workers runtime). You must use the Web Crypto API directly.

---

## Context

**Web Push** works via a standardised protocol:
- The browser subscribes to a push service (Google FCM, Mozilla Autopush, Apple APNs via
  browser abstraction) and returns a `PushSubscription` containing an `endpoint` URL,
  `p256dh` (client's ECDH public key), and `auth` (random 16-byte secret).
- The server sends an HTTP POST to the endpoint with an encrypted payload signed using
  VAPID (Voluntary Application Server Identification).
- The browser's service worker receives the push and shows a notification.

Node's `web-push` package handles VAPID signing and payload encryption. In Cloudflare
Workers (which run V8 isolates, not Node), you must reimplement this using:
- `crypto.subtle` — available in Workers since `compatibility_date = "2022-01-31"`
- `TextEncoder` / `ArrayBuffer` — standard in the Workers runtime

## Section 1 — Generating VAPID Keys

Generate keys once outside the Worker (Node.js script, run locally):

```ts
// scripts/generate-vapid-keys.ts
import { generateVAPIDKeys } from 'web-push';

const keys = generateVAPIDKeys();
console.log('VAPID_PUBLIC_KEY=', keys.publicKey);
console.log('VAPID_PRIVATE_KEY=', keys.privateKey);
// Output is URL-safe base64 encoded — store in wrangler secrets
```

Store as Worker secrets (never commit to source):

```bash
wrangler secret put VAPID_PUBLIC_KEY
wrangler secret put VAPID_PRIVATE_KEY
wrangler secret put VAPID_SUBJECT  # e.g. mailto:admin@example.com
```

In `wrangler.toml` declare the binding types so TypeScript knows about them:

```toml
# wrangler.toml
[[d1_databases]]
binding = "DB"
database_name = "push-subscriptions"
database_id = "xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx"
```

## Section 2 — Browser Subscription (Next.js Client)

The subscription flow runs in a Client Component, guarded by permission checks:

```tsx
// components/push-subscribe-button.tsx
'use client';

import { useState } from 'react';
import { subscribeToPush } from '@/app/actions/push-actions';

const VAPID_PUBLIC_KEY = process.env.NEXT_PUBLIC_VAPID_PUBLIC_KEY!;

function urlBase64ToUint8Array(base64: string): Uint8Array {
  const padding = '='.repeat((4 - (base64.length % 4)) % 4);
  const b64 = (base64 + padding).replace(/-/g, '+').replace(/_/g, '/');
  const raw = atob(b64);
  return Uint8Array.from(raw, (c) => c.charCodeAt(0));
}

export function PushSubscribeButton() {
  const [status, setStatus] = useState<'idle' | 'loading' | 'subscribed' | 'denied'>('idle');

  async function handleSubscribe() {
    if (!('serviceWorker' in navigator) || !('PushManager' in window)) {
      alert('Push notifications are not supported in this browser.');
      return;
    }

    setStatus('loading');

    try {
      const permission = await Notification.requestPermission();
      if (permission !== 'granted') {
        setStatus('denied');
        return;
      }

      const reg = await navigator.serviceWorker.ready;
      const subscription = await reg.pushManager.subscribe({
        userVisibleOnly: true,
        applicationServerKey: urlBase64ToUint8Array(VAPID_PUBLIC_KEY),
      });

      // Send subscription JSON to the server action / API route
      await subscribeToPush(JSON.stringify(subscription));
      setStatus('subscribed');
    } catch (err) {
      console.error('Push subscription failed', err);
      setStatus('idle');
    }
  }

  return (
    <button
      onClick={handleSubscribe}
      disabled={status === 'loading' || status === 'subscribed'}
      // Mobile: minimum 44×44 px tap target (WCAG 2.5.5)
      style={{ minHeight: 44, minWidth: 44, padding: '10px 20px' }}
    >
      {status === 'subscribed' ? 'Notifications on ✓' : 'Enable Notifications'}
    </button>
  );
}
```

Expose the public key via `NEXT_PUBLIC_` prefix so it bakes into the client bundle:

```bash
# .env.local  (build time only — public key is not sensitive)
NEXT_PUBLIC_VAPID_PUBLIC_KEY=BExxxxxxxxxxxxxxxxxxxxxx...
```

## Section 3 — Service Worker Push Handler

```js
// public/sw.js  (or generated by next-pwa / your build step)
self.addEventListener('push', (event) => {
  if (!event.data) return;

  let payload;
  try {
    payload = event.data.json();
  } catch {
    payload = { title: 'New notification', body: event.data.text(), icon: '/icon-192.png' };
  }

  const { title, body, icon = '/icon-192.png', badge = '/badge-72.png', url = '/' } = payload;

  event.waitUntil(
    self.registration.showNotification(title, {
      body,
      icon,
      badge,          // shown in Android status bar
      data: { url },
      // vibrate works on Android; silently ignored on iOS
      vibrate: [200, 100, 200],
    })
  );
});

self.addEventListener('notificationclick', (event) => {
  event.notification.close();
  const targetUrl = event.notification.data?.url ?? '/';
  event.waitUntil(
    clients.matchAll({ type: 'window', includeUncontrolled: true }).then((wins) => {
      const existing = wins.find((w) => w.url === targetUrl);
      return existing ? existing.focus() : clients.openWindow(targetUrl);
    })
  );
});
```

Register the service worker from the Next.js root layout:

```tsx
// app/layout.tsx  (partial)
'use client';
import { useEffect } from 'react';

export function ServiceWorkerRegistrar() {
  useEffect(() => {
    if ('serviceWorker' in navigator) {
      navigator.serviceWorker.register('/sw.js', { scope: '/' }).catch(console.error);
    }
  }, []);
  return null;
}
```

## Section 4 — Sending Pushes from Cloudflare Workers (VAPID + Encryption)

The Workers-compatible VAPID signing and payload encryption reuses `crypto.subtle`:

```ts
// worker/src/lib/web-push.ts

/** Convert URL-safe base64 string to ArrayBuffer */
function b64ToBuffer(b64: string): ArrayBuffer {
  const padding = '='.repeat((4 - (b64.length % 4)) % 4);
  const bin = atob((b64 + padding).replace(/-/g, '+').replace(/_/g, '/'));
  const buf = new Uint8Array(bin.length);
  for (let i = 0; i < bin.length; i++) buf[i] = bin.charCodeAt(i);
  return buf.buffer;
}

function bufToB64Url(buf: ArrayBuffer): string {
  return btoa(String.fromCharCode(...new Uint8Array(buf)))
    .replace(/\+/g, '-')
    .replace(/\//g, '_')
    .replace(/=/g, '');
}

async function importVapidPrivateKey(b64: string): Promise<CryptoKey> {
  return crypto.subtle.importKey(
    'pkcs8',
    b64ToBuffer(b64),
    { name: 'ECDSA', namedCurve: 'P-256' },
    false,
    ['sign']
  );
}

async function buildVapidHeaders(
  endpoint: string,
  subject: string,
  publicKeyB64: string,
  privateKeyB64: string
): Promise<{ Authorization: string; 'Crypto-Key': string }> {
  const audience = new URL(endpoint).origin;
  const expiry = Math.floor(Date.now() / 1000) + 12 * 3600; // 12 h

  const header = { typ: 'JWT', alg: 'ES256' };
  const claims = { aud: audience, exp: expiry, sub: subject };

  const enc = new TextEncoder();
  const h = bufToB64Url(enc.encode(JSON.stringify(header)).buffer);
  const c = bufToB64Url(enc.encode(JSON.stringify(claims)).buffer);
  const signingInput = `${h}.${c}`;

  const key = await importVapidPrivateKey(privateKeyB64);
  const sig = await crypto.subtle.sign(
    { name: 'ECDSA', hash: { name: 'SHA-256' } },
    key,
    enc.encode(signingInput)
  );

  const jwt = `${signingInput}.${bufToB64Url(sig)}`;
  return {
    Authorization: `vapid t=${jwt},k=${publicKeyB64}`,
    'Crypto-Key': `p256ecdsa=${publicKeyB64}`,
  };
}

export interface PushSubscriptionData {
  endpoint: string;
  keys: { p256dh: string; auth: string };
}

export interface PushPayload {
  title: string;
  body: string;
  url?: string;
  icon?: string;
}

/**
 * Sends an encrypted Web Push message to a single subscriber.
 * Encryption uses the aesgcm scheme (RFC 8291 / draft-ietf-webpush-encryption).
 * For production consider the `web-push-encryption` library compiled to WASM.
 */
export async function sendWebPush(
  sub: PushSubscriptionData,
  payload: PushPayload,
  env: { VAPID_PUBLIC_KEY: string; VAPID_PRIVATE_KEY: string; VAPID_SUBJECT: string }
): Promise<Response> {
  const vapidHeaders = await buildVapidHeaders(
    sub.endpoint,
    env.VAPID_SUBJECT,
    env.VAPID_PUBLIC_KEY,
    env.VAPID_PRIVATE_KEY
  );

  // Minimal unencrypted push for browsers that support it (e.g. Firefox, no payload encryption)
  // For production, implement RFC 8291 aesgcm128 or use a WASM-compiled web-push library.
  const body = JSON.stringify(payload);
  const bodyBytes = new TextEncoder().encode(body);

  const res = await fetch(sub.endpoint, {
    method: 'POST',
    headers: {
      ...vapidHeaders,
      'Content-Type': 'application/octet-stream',
      'Content-Length': String(bodyBytes.byteLength),
      TTL: '86400',
    },
    body: bodyBytes,
  });

  return res;
}
```

Worker endpoint that broadcasts:

```ts
// worker/src/routes/push-send.ts
import { sendWebPush } from '../lib/web-push';

export async function handlePushBroadcast(
  request: Request,
  env: Env
): Promise<Response> {
  // Authenticate — only internal service calls should reach this
  const authHeader = request.headers.get('Authorization');
  if (authHeader !== `Bearer ${env.INTERNAL_API_SECRET}`) {
    return new Response('Unauthorized', { status: 401 });
  }

  const { payload } = await request.json<{ payload: { title: string; body: string; url?: string } }>();

  // Load all subscriptions from D1
  const { results } = await env.DB.prepare('SELECT subscription_json FROM push_subscriptions')
    .all<{ subscription_json: string }>();

  const sends = results.map(async (row) => {
    const sub = JSON.parse(row.subscription_json);
    try {
      const res = await sendWebPush(sub, payload, env);
      if (res.status === 410 || res.status === 404) {
        // Subscription expired — clean up
        await env.DB.prepare('DELETE FROM push_subscriptions WHERE endpoint = ?')
          .bind(sub.endpoint)
          .run();
      }
    } catch (err) {
      console.error('Push failed for', sub.endpoint, err);
    }
  });

  await Promise.allSettled(sends);
  return Response.json({ sent: results.length });
}
```

## Anti-patterns

- **Storing VAPID private key in `wrangler.toml` or source code** — use `wrangler secret put`
  only. The private key gives anyone the ability to send pushes to all your subscribers.
- **Sending pushes synchronously from a route handler** — on large subscriber lists this will
  time out (Workers have a 30-second CPU time limit). Use a Queue or Durable Object to fan
  out in batches.
- **Not cleaning up 410/404 subscription responses** — expired subscriptions accumulate and
  cause silent failures; always delete on `410 Gone` or `404 Not Found` from the push service.
- **Using `userVisibleOnly: false`** — background sync pushes without visible notifications
  are disallowed by Chrome and will cause subscription failures on Chromium-based browsers.

---

## Gotchas

- **iOS/Safari**: Web Push on iOS requires Safari 16.4+ and the site must be installed as a
  PWA (added to Home Screen) for push to work. A `manifest.json` with valid icons is required.
- **VAPID JWT expiry**: keep it ≤ 24 hours. Many push services reject JWTs with `exp` more
  than 24 hours in the future.
- **Payload encryption**: the example above sends unencrypted payload for simplicity. For
  full RFC 8291 `aesgcm` encryption (required by some push services for payload confidentiality),
  you need the ECDH shared secret derivation using `crypto.subtle.deriveBits` with the
  subscriber's `p256dh` key. This is non-trivial; use a WASM build of a push encryption
  library for production.
- **Workers CPU time**: ECDSA signing via `crypto.subtle` is fast (< 1 ms), but if you fan
  out to thousands of subscribers in a single Worker invocation you may hit the CPU limit.
  Use Queues (`env.PUSH_QUEUE.send`) to distribute work.
- **`NEXT_PUBLIC_VAPID_PUBLIC_KEY`** is baked into the client bundle at build time. If you
  rotate the key pair, you must redeploy the Next.js app AND migrate all existing subscriptions
  (they're tied to the old public key and will fail with the new one).

## Verification

1. Register SW in browser, click subscribe, confirm `Notification.permission === 'granted'`
   and `PushSubscription` appears in DevTools → Application → Push Messaging.
2. Confirm subscription row in D1: `wrangler d1 execute push-subscriptions --command "SELECT * FROM push_subscriptions LIMIT 1"`
3. POST to the Worker broadcast endpoint with `curl -X POST ... -d '{"payload":{"title":"Test","body":"Hello"}}'`
4. Notification should appear on desktop within 1–2 seconds.
5. On iOS (Safari 16.4+, added to Home Screen), repeat and confirm notification appears while
   the app is backgrounded.
