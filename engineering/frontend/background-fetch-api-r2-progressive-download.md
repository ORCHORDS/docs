# Background Fetch API: Progressive Downloads with R2 and Workers

- **Date**: 2026-08-23
- **Author**: example.com
- **Status**: production

## Symptom / Use-case
Users need to download large files (video exports, data archives, offline asset bundles) from R2 without losing progress when they close or background the tab. A standard `fetch()` is tied to the page lifecycle and is aborted the moment the tab goes away. The Background Fetch API allows the browser to continue the download through the service worker even when the page is closed.

## Context
The Background Fetch API (`BackgroundFetchManager`) is available in Chrome/Edge 74+ and Android Chrome but is not yet in Firefox or Safari — treat it as a progressive enhancement. The service worker registers the download, the browser shows native UI progress, and the service worker's `backgroundfetchsuccess` event is fired even if the page was never reopened. Files are served as presigned R2 URLs generated by a Cloudflare Worker so they expire safely. The downloaded responses are stored in a `Cache` API cache managed by the service worker for later retrieval.

## Generating Presigned R2 URLs in Workers

```typescript
// workers/download-tokens.ts
import { AwsClient } from "aws4fetch";
import { Env } from "./types";

interface DownloadToken {
  url: string;
  filename: string;
  sizeBytes: number;
  expiresAt: string;
}

export async function generateDownloadToken(
  env: Env,
  objectKey: string
): Promise<DownloadToken> {
  const client = new AwsClient({
    accessKeyId: env.R2_ACCESS_KEY_ID,
    secretAccessKey: env.R2_SECRET_ACCESS_KEY,
    region: "auto",
    service: "s3",
  });

  // Get object metadata first to provide size hint to BackgroundFetch
  const headRes = await client.fetch(
    `https://${env.R2_BUCKET}.${env.R2_ACCOUNT_ID}.r2.cloudflarestorage.com/${objectKey}`,
    { method: "HEAD" }
  );
  if (!headRes.ok) throw new Error(`R2 HEAD failed: ${headRes.status}`);
  const sizeBytes = Number(headRes.headers.get("content-length") ?? "0");

  // Generate a 1-hour presigned GET URL
  const expiresIn = 3600;
  const expires = new Date(Date.now() + expiresIn * 1000);
  const signedUrl = await client.sign(
    new Request(
      `https://${env.R2_BUCKET}.${env.R2_ACCOUNT_ID}.r2.cloudflarestorage.com/${objectKey}`,
      { method: "GET" }
    ),
    {
      aws: { signQuery: true },
      headers: { "X-Amz-Expires": String(expiresIn) },
    }
  );

  return {
    url: signedUrl.url,
    filename: objectKey.split("/").pop() ?? objectKey,
    sizeBytes,
    expiresAt: expires.toISOString(),
  };
}

export default {
  async fetch(request: Request, env: Env): Promise<Response> {
    if (request.method !== "GET") {
      return new Response("Method Not Allowed", { status: 405 });
    }
    const url = new URL(request.url);
    const key = url.searchParams.get("key");
    if (!key) return new Response("Missing key", { status: 400 });

    // Validate the user has access to this key (JWT check omitted for brevity)
    const token = await generateDownloadToken(env, key);
    return new Response(JSON.stringify(token), {
      headers: { "Content-Type": "application/json" },
    });
  },
};
```

## Service Worker: Handling Background Fetch Lifecycle

```typescript
// public/service-worker.ts (built separately — not a Workers script)
/// <reference lib="webworker" />

declare const self: ServiceWorkerGlobalScope;

const DOWNLOAD_CACHE = "bg-downloads-v1";

// Store a record of all active background fetches for UI updates
const activeDownloads = new Map<string, BackgroundFetchRegistration>();

self.addEventListener("backgroundfetchsuccess", (event) => {
  const registration = event.registration;

  event.waitUntil(
    (async () => {
      const cache = await caches.open(DOWNLOAD_CACHE);

      // Store all fetched responses in the cache
      const records = await registration.matchAll();
      await Promise.all(
        records.map(async (record) => {
          const response = await record.responseReady;
          await cache.put(record.request, response.clone());
        })
      );

      // Notify any open clients that the download is complete
      const clients = await self.clients.matchAll({ type: "window" });
      clients.forEach((client) =>
        client.postMessage({
          type: "BG_FETCH_SUCCESS",
          id: registration.id,
          title: registration.title,
        })
      );
    })()
  );
});

self.addEventListener("backgroundfetchfail", (event) => {
  const registration = event.registration;
  self.clients.matchAll({ type: "window" }).then((clients) =>
    clients.forEach((client) =>
      client.postMessage({
        type: "BG_FETCH_FAIL",
        id: registration.id,
        failureReason: registration.failureReason,
      })
    )
  );
});

self.addEventListener("backgroundfetchclick", (event) => {
  // User clicked the native download progress notification
  event.waitUntil(
    self.clients
      .openWindow("/downloads")
      .then((client) => client?.focus())
  );
});

// Serve downloaded files from cache on subsequent page loads
self.addEventListener("fetch", (event) => {
  const url = new URL(event.request.url);
  if (url.pathname.startsWith("/download/")) {
    event.respondWith(
      caches.match(event.request, { cacheName: DOWNLOAD_CACHE }).then(
        (cached) => cached ?? fetch(event.request)
      )
    );
  }
});
```

## React Hook: Initiating and Tracking Background Fetches

```tsx
// hooks/useBackgroundFetch.ts
import { useState, useEffect, useCallback } from "react";

interface DownloadState {
  id: string;
  title: string;
  progress: number; // 0–100
  status: "pending" | "downloading" | "success" | "fail";
  failureReason?: string;
}

function isBgFetchSupported(): boolean {
  return (
    "serviceWorker" in navigator &&
    "BackgroundFetchManager" in self
  );
}

export function useBackgroundFetch() {
  const [downloads, setDownloads] = useState<Map<string, DownloadState>>(
    new Map()
  );

  // Listen for SW messages
  useEffect(() => {
    const handler = (event: MessageEvent) => {
      const { type, id, title, failureReason } = event.data ?? {};
      if (type === "BG_FETCH_SUCCESS") {
        setDownloads((prev) => {
          const next = new Map(prev);
          next.set(id, { id, title, progress: 100, status: "success" });
          return next;
        });
      } else if (type === "BG_FETCH_FAIL") {
        setDownloads((prev) => {
          const next = new Map(prev);
          next.set(id, {
            id,
            title,
            progress: 0,
            status: "fail",
            failureReason,
          });
          return next;
        });
      }
    };
    navigator.serviceWorker.addEventListener("message", handler);
    return () =>
      navigator.serviceWorker.removeEventListener("message", handler);
  }, []);

  const startDownload = useCallback(
    async (objectKey: string, title: string) => {
      if (!isBgFetchSupported()) {
        // Fallback: standard fetch + <a download> trigger
        const tokenRes = await fetch(`/api/download-token?key=<redacted-secret>
        const { url } = await tokenRes.json();
        const a = document.createElement("a");
        a.href = url;
        a.download = objectKey.split("/").pop() ?? "download";
        a.click();
        return;
      }

      // Get presigned URL from the Worker
      const tokenRes = await fetch(`/api/download-token?key=<redacted-secret>
      const { url, sizeBytes, filename } = await tokenRes.json();

      const reg = await navigator.serviceWorker.ready;
      const bgFetch = await reg.backgroundFetch.fetch(
        objectKey, // download ID
        [url],
        {
          title,
          downloadTotal: sizeBytes,
          icons: [{ src: "/icons/download-192.png", sizes: "192x192" }],
        }
      );

      const id = bgFetch.id;
      setDownloads((prev) => {
        const next = new Map(prev);
        next.set(id, { id, title, progress: 0, status: "pending" });
        return next;
      });

      // Poll progress every 500 ms while the page is open
      const interval = setInterval(async () => {
        const existing = await reg.backgroundFetch.get(id);
        if (!existing) {
          clearInterval(interval);
          return;
        }
        const progress =
          existing.downloadTotal > 0
            ? Math.round(
                (existing.downloaded / existing.downloadTotal) * 100
              )
            : 0;
        setDownloads((prev) => {
          const next = new Map(prev);
          next.set(id, { id, title, progress, status: "downloading" });
          return next;
        });
        if (
          existing.result === "success" ||
          existing.result === "failure"
        ) {
          clearInterval(interval);
        }
      }, 500);
    },
    []
  );

  return { downloads: [...downloads.values()], startDownload };
}
```

## Retrieving a Completed Download

```typescript
// lib/bg-fetch-retrieve.ts

export async function getDownloadedFile(
  cacheKey: string
): Promise<Blob | null> {
  const cache = await caches.open("bg-downloads-v1");
  const response = await cache.match(cacheKey);
  if (!response) return null;
  return response.blob();
}

// Offer the blob to the user via a temporary object URL
export function triggerSaveAs(blob: Blob, filename: string): void {
  const url = URL.createObjectURL(blob);
  const a = document.createElement("a");
  a.href = url;
  a.download = filename;
  document.body.appendChild(a);
  a.click();
  document.body.removeChild(a);
  // Clean up after a short delay so the browser can initiate the download
  setTimeout(() => URL.revokeObjectURL(url), 5000);
}
```

## Anti-patterns

- **Using Background Fetch for small files** — The API has overhead from service worker registration and native UI. For files under ~5 MB, a standard `fetch()` with a progress stream is simpler and more widely supported.
- **Not providing `downloadTotal`** — Without it, the native progress UI shows an indeterminate spinner. Always HEAD the R2 object first to get `Content-Length`.
- **Storing the raw presigned URL in the background fetch ID** — IDs are visible to the service worker and logged in DevTools. Use an opaque ID (the object key) and generate the URL server-side only at fetch time.
- **Not handling the `backgroundfetchfail` event** — If the presigned URL expires before the download completes (the user backgrounds the app for over an hour), the download silently fails without a `backgroundfetchfail` handler.
- **Caching without a cache eviction strategy** — Downloads accumulate in the `Cache` API indefinitely. Implement a TTL check or a "clear completed downloads" UI that calls `cache.delete()`.

## Gotchas

- **Firefox and Safari do not support Background Fetch** — Always implement the fallback path (standard fetch + object URL). Feature detection via `"BackgroundFetchManager" in self` is reliable.
- **Service worker scope must cover the fetch URLs** — If the R2 presigned URL domain differs from your Pages domain, the service worker cannot intercept it. This is fine for the fetch itself (the browser handles it natively), but `backgroundfetchsuccess` still fires on your service worker regardless of the URL origin.
- **Background Fetch requires user permission on some platforms** — On Android, the app must have notification permission since the download progress is shown in the notification shade. Prompt for permission before calling `backgroundFetch.fetch()`.
- **`registration.backgroundFetch.get()` returns `undefined` after success** — Once the `backgroundfetchsuccess` event fires and the registration is resolved, subsequent `get()` calls return `undefined`. Read progress only while `result` is `""` (pending).
- **Cloudflare Workers presigned URL clock skew** — Workers use UTC; R2 presigned URLs are time-sensitive. If you generate a URL and the client starts the background fetch days later, it will fail. Set `downloadTotal` and use an expiry well beyond the expected download time.
