# Wrangler Types Auto-Generation CI Pipeline

- Date: 2026-08-22
- Author: example.com
- Status: production

## Keeping Workers TypeScript Types in Sync with Bindings

Cloudflare Workers bindings — D1 databases, KV namespaces, R2 buckets, Queues, Services — all need accurate TypeScript types for safe usage inside a Worker. Maintaining these types by hand means they drift the moment `wrangler.toml` is updated, leading to runtime errors that the type-checker cannot catch.

`wrangler types` solves this by reading the live `wrangler.toml` and emitting a `worker-configuration.d.ts` ambient declaration file that matches every bound resource. When this command runs automatically in CI alongside `tsc --noEmit`, type mismatches between the binding configuration and the Worker source surface as compile errors before deployment, not after.

This article covers the full pipeline: local development workflow, the generated file format, a GitHub Actions job that blocks merges on binding drift, and verification patterns for D1, KV, R2, and Queues.

## Context

- Runtime: Cloudflare Workers (no Node.js compatibility needed for this workflow)
- Language: TypeScript 5.x with `strict: true`
- Tooling: Wrangler 4.x, pnpm workspaces, Turborepo
- CI: GitHub Actions
- Binding types covered: D1Database, KVNamespace, R2Bucket, Queue

## Generating `worker-configuration.d.ts` Locally

Add a `types` script to each Worker's `package.json` alongside `dev` and `deploy`:

```json
{
  "scripts": {
    "types": "wrangler types",
    "types:check": "wrangler types && tsc --noEmit",
    "dev": "wrangler dev",
    "deploy": "wrangler deploy"
  }
}
```

Run it after any `wrangler.toml` change:

```bash
pnpm run types
```

The generated file at `worker-configuration.d.ts` looks like this for a typical Worker:

```typescript
// Generated by Wrangler — do not edit manually
interface Env {
  DB: D1Database;
  CACHE: KVNamespace;
  ASSETS: R2Bucket;
  NOTIFICATION_QUEUE: Queue<{ userId: string; event: string }>;
  API_SECRET: string;
}
```

Commit this file alongside `wrangler.toml`. It is intentionally tracked so reviewers see binding changes expressed as TypeScript diffs.

## Consuming Binding Types in Worker Source

With `worker-configuration.d.ts` present, the `Env` interface is available globally. Reference it in fetch handlers and Durable Objects:

```typescript
// src/index.ts
import { Hono } from "hono";

const app = new Hono<{ Bindings: Env }>();

app.get("/users/:id", async (c) => {
  const db = c.env.DB; // typed as D1Database
  const stmt = db.prepare("SELECT * FROM users WHERE id = ?");
  const user = await stmt.bind(c.req.param("id")).first<{
    id: string;
    name: string;
    email: string;
  }>();
  if (!user) return c.json({ error: "not found" }, 404);
  return c.json(user);
});

app.post("/cache/:key", async (c) => {
  const body = await c.req.json<{ value: string; ttl?: number }>();
  await c.env.CACHE.put(c.req.param("key"), body.value, {
    expirationTtl: body.ttl ?? 3600,
  });
  return c.json({ ok: true });
});

export default app;
```

## GitHub Actions CI Pipeline

Create `.github/workflows/workers-typecheck.yml`:

```yaml
name: Workers Type Check

on:
  push:
    branches: [main]
  pull_request:
    branches: [main]

jobs:
  typecheck:
    name: Type-check Workers bindings
    runs-on: ubuntu-latest
    permissions:
      contents: read

    steps:
      - uses: actions/checkout@v4

      - uses: pnpm/action-setup@v4
        with:
          version: 9

      - uses: actions/setup-node@v4
        with:
          node-version: 22
          cache: pnpm

      - name: Install dependencies
        run: pnpm install --frozen-lockfile

      - name: Regenerate wrangler types
        run: pnpm --filter "./apps/api" run types
        env:
          # wrangler types reads wrangler.toml but does not need auth
          CLOUDFLARE_API_TOKEN: ${{ secrets.CLOUDFLARE_API_TOKEN }}

      - name: Fail on binding drift
        run: |
          if ! git diff --exit-code worker-configuration.d.ts; then
            echo "::error::worker-configuration.d.ts is out of date. Run 'pnpm run types' locally and commit the result."
            exit 1
          fi

      - name: Type-check all Workers
        run: pnpm --filter "./apps/*" run tsc --noEmit

      - name: Report binding summary
        if: always()
        run: |
          echo "### Binding types verified" >> $GITHUB_STEP_SUMMARY
          grep -E "^\s+(DB|CACHE|ASSETS|NOTIFICATION_QUEUE|API_SECRET)" \
            apps/api/worker-configuration.d.ts >> $GITHUB_STEP_SUMMARY || true
```

## Verifying Specific Binding Types

Run targeted type tests for each binding kind using `tsc`-compatible assertions:

```typescript
// src/__tests__/binding-types.test.ts
// Not executed at runtime — a compile-time verification file
import type {} from "../worker-configuration";

// D1 type accuracy
declare const env: Env;
const _d1: D1Database = env.DB;
const _stmt: D1PreparedStatement = env.DB.prepare("SELECT 1");

// KV type accuracy
const _kv: KVNamespace = env.CACHE;
const _kvGet: Promise<string | null> = env.CACHE.get("key");

// R2 type accuracy
const _r2: R2Bucket = env.ASSETS;
const _r2Get: Promise<R2Object | null> = env.ASSETS.head("object-key");

// Queue type accuracy — generic parameter flows through
const _queue: Queue<{ userId: string; event: string }> =
  env.NOTIFICATION_QUEUE;
const _send: Promise<void> = env.NOTIFICATION_QUEUE.send({
  userId: "u1",
  event: "signup",
});

// Secret is a plain string, not a special type
const _secret: string = env.API_SECRET;
```

Add this to `tsconfig.json` include so `tsc --noEmit` covers it:

```json
{
  "compilerOptions": {
    "strict": true,
    "target": "ES2022",
    "lib": ["ES2022"],
    "types": ["@cloudflare/workers-types/2023-07-01"]
  },
  "include": ["src/**/*.ts", "worker-configuration.d.ts"]
}
```

## Turborepo Task Configuration

In the monorepo root `turbo.json`, wire `types` into the pipeline so it runs before `typecheck`:

```json
{
  "$schema": "https://turbo.build/schema.json",
  "tasks": {
    "types": {
      "outputs": ["worker-configuration.d.ts"],
      "inputs": ["wrangler.toml"]
    },
    "typecheck": {
      "dependsOn": ["types"],
      "outputs": []
    },
    "build": {
      "dependsOn": ["typecheck"]
    }
  }
}
```

## Anti-patterns

- Committing `worker-configuration.d.ts` to `.gitignore` — reviewers lose visibility into binding changes and CI cannot detect drift
- Writing manual `interface Env` declarations in `src/types.ts` that shadow the generated file — they silently diverge
- Running `wrangler types` only in a pre-deploy hook — type errors surface too late to block bad PRs
- Using `any` to cast binding access when the generated type does not match — the underlying issue is a stale `wrangler.toml` or outdated `@cloudflare/workers-types`
- Skipping the `Queue` generic parameter — without it, `send()` accepts anything and payload shape bugs are invisible

## Gotchas

- `wrangler types` requires `CLOUDFLARE_API_TOKEN` in CI even though it only reads local config — this is a Wrangler CLI initialization requirement, not a remote API call
- The generated file uses `interface Env` (not `type Env`), so merging additional properties requires `interface` declaration merging in a separate `.d.ts`, not intersection types
- `@cloudflare/workers-types` version must align with the compatibility date in `wrangler.toml`; a mismatch causes spurious type errors on recently added APIs
- Wrangler 4 changed the output path from `./worker-configuration.d.ts` to honoring `--outfile`; pin the path explicitly if using a custom `outfile` flag
- `D1Database` query result generics require explicit type parameters on `.first<T>()`, `.all<T>()` — the generated binding type alone does not infer row shapes

## Verification

```bash
# Regenerate types and confirm no drift
pnpm run types
git diff --exit-code worker-configuration.d.ts

# Full type check including binding assertions
pnpm run tsc --noEmit

# Check Turborepo picks up types as a dependency of typecheck
pnpm turbo run typecheck --dry-run 2>&1 | grep -A3 "types"

# Verify workers-types version aligns with compatibility date
grep "compatibility_date" wrangler.toml
pnpm list @cloudflare/workers-types
```
