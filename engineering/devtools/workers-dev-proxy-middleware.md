# Local Development Proxy Middleware for Workers

Date: 2026-08-24 / Author: example.com / Status: production

---

## Symptom / Use-case

You are building a full-stack application: the backend is a Cloudflare Worker and the frontend is a Vite (or Next.js) dev server. During local development you want:

- API calls (`/api/*`) routed to the Worker running under `wrangler dev`.
- Static assets and page requests routed to the Vite dev server with HMR.
- A single origin (`http://localhost:5173`) so the browser never hits CORS issues.
- Environment variables injected consistently between the Worker and the frontend build.
- Optional HTTPS for testing `Secure` cookies and `navigator.serviceWorker` without a production deployment.

---

## Context

`wrangler dev` starts the Worker on `http://127.0.0.1:8787` by default. Vite starts on `http://localhost:5173`. Without a proxy, the browser must make cross-origin requests from `localhost:5173` to `localhost:8787`, triggering CORS pre-flights and invalidating `SameSite=Lax` cookies.

The cleanest solution is a lightweight proxy dev server that:
1. Listens on a single port (e.g. 5173 or a dedicated 4000).
2. Forwards `/api/*` (and other Worker routes) to `wrangler dev`.
3. Forwards everything else to the Vite dev server, preserving WebSocket upgrade for HMR.

This can be implemented as a Node.js script using the `http-proxy` or `http-proxy-middleware` package, or as a Vite plugin.

---

## Solution

```typescript
// dev-proxy/server.ts — standalone proxy server
import * as http from 'http';
import * as https from 'https';
import * as fs from 'fs';
import { createProxyMiddleware, type Options } from 'http-proxy-middleware';
import type { IncomingMessage, ServerResponse } from 'http';

const WORKER_ORIGIN = process.env.WORKER_ORIGIN ?? 'http://127.0.0.1:8787';
const VITE_ORIGIN = process.env.VITE_ORIGIN ?? 'http://localhost:5173';
const PROXY_PORT = Number(process.env.PROXY_PORT ?? 4000);
const USE_HTTPS = process.env.USE_HTTPS === 'true';

/** Routes that should be forwarded to the Worker instead of Vite. */
const WORKER_ROUTES: RegExp[] = [
  /^\/api\//,
  /^\/auth\//,
  /^\/webhook\//,
  /^\/health$/,
];

function isWorkerRoute(pathname: string): boolean {
  return WORKER_ROUTES.some((re) => re.test(pathname));
}

const workerProxy = createProxyMiddleware<IncomingMessage, ServerResponse>({
  target: WORKER_ORIGIN,
  changeOrigin: true,
  // Inject dev-only headers the Worker can use to distinguish local requests
  on: {
    proxyReq: (proxyReq) => {
      proxyReq.setHeader('X-Dev-Proxy', '1');
      proxyReq.setHeader('X-Forwarded-Host', `localhost:${PROXY_PORT}`);
    },
    error: (err, _req, res) => {
      console.error('[worker-proxy] error:', err.message);
      if (res instanceof ServerResponse) {
        res.writeHead(502);
        res.end(JSON.stringify({ error: 'Worker unavailable', detail: err.message }));
      }
    },
  },
} as Options);

const viteProxy = createProxyMiddleware<IncomingMessage, ServerResponse>({
  target: VITE_ORIGIN,
  changeOrigin: true,
  // Proxy WebSocket connections for Vite HMR
  ws: true,
  on: {
    error: (err, _req, res) => {
      console.error('[vite-proxy] error:', err.message);
      if (res instanceof ServerResponse) {
        res.writeHead(502);
        res.end('Vite dev server unavailable. Run: npm run dev:vite');
      }
    },
  },
} as Options);

const requestHandler: http.RequestListener = (req, res) => {
  const pathname = new URL(req.url ?? '/', `http://localhost`).pathname;

  // CORS pre-flight: always allow in local dev
  if (req.method === 'OPTIONS') {
    res.writeHead(204, {
      'Access-Control-Allow-Origin': '*',
      'Access-Control-Allow-Methods': 'GET,POST,PUT,PATCH,DELETE,OPTIONS',
      'Access-Control-Allow-Headers': 'Content-Type,Authorization,X-Requested-With',
      'Access-Control-Max-Age': '86400',
    });
    res.end();
    return;
  }

  if (isWorkerRoute(pathname)) {
    console.log(`[proxy] → worker  ${req.method} ${pathname}`);
    workerProxy(req, res, () => {});
  } else {
    viteProxy(req, res, () => {});
  }
};

function startServer(): void {
  let server: http.Server | https.Server;

  if (USE_HTTPS) {
    // Expects a self-signed cert generated by mkcert or similar
    const sslOptions = {
      key: fs.readFileSync('./dev-proxy/localhost-key.pem'),
      cert: fs.readFileSync('./dev-proxy/localhost.pem'),
    };
    server = https.createServer(sslOptions, requestHandler);
    console.log(`Dev proxy (HTTPS) → https://localhost:${PROXY_PORT}`);
  } else {
    server = http.createServer(requestHandler);
    console.log(`Dev proxy (HTTP) → http://localhost:${PROXY_PORT}`);
  }

  // Forward WebSocket upgrades (Vite HMR)
  server.on('upgrade', (req, socket, head) => {
    const pathname = new URL(req.url ?? '/', 'http://localhost').pathname;
    if (!isWorkerRoute(pathname)) {
      viteProxy.upgrade!(req, socket as never, head);
    }
  });

  server.listen(PROXY_PORT, '0.0.0.0', () => {
    console.log(`  Worker API:   ${WORKER_ORIGIN}`);
    console.log(`  Vite server:  ${VITE_ORIGIN}`);
  });
}

startServer();
```

```typescript
// vite.config.ts — alternative: use Vite's built-in proxy instead of a standalone server
import { defineConfig, loadEnv } from 'vite';
import react from '@vitejs/plugin-react';

export default defineConfig(({ mode }) => {
  const env = loadEnv(mode, process.cwd(), '');
  const workerUrl = env.WORKER_ORIGIN ?? 'http://127.0.0.1:8787';

  return {
    plugins: [react()],
    server: {
      port: 5173,
      proxy: {
        '/api': {
          target: workerUrl,
          changeOrigin: true,
          configure: (proxy) => {
            proxy.on('error', (err) => {
              console.error('[vite-proxy] Worker error:', err.message);
            });
            proxy.on('proxyReq', (proxyReq) => {
              proxyReq.setHeader('X-Dev-Proxy', '1');
            });
          },
        },
        '/auth': { target: workerUrl, changeOrigin: true },
        '/health': { target: workerUrl, changeOrigin: true },
      },
    },
    define: {
      // Inject build-time env vars into the Vite frontend
      __APP_ENV__: JSON.stringify(env.ENVIRONMENT ?? 'development'),
      __WORKER_URL__: JSON.stringify(workerUrl),
    },
  };
});
```

```typescript
// src/index.ts — Worker: handle X-Dev-Proxy header to relax local restrictions
export default {
  async fetch(request: Request, env: Env): Promise<Response> {
    const isLocalDev = request.headers.get('X-Dev-Proxy') === '1';

    const response = await handleRequest(request, env);

    // Add CORS headers in local dev so the frontend can also call the Worker directly
    if (isLocalDev) {
      const headers = new Headers(response.headers);
      headers.set('Access-Control-Allow-Origin', request.headers.get('Origin') ?? '*');
      headers.set('Access-Control-Allow-Credentials', 'true');
      return new Response(response.body, { status: response.status, headers });
    }

    return response;
  },
} satisfies ExportedHandler<Env>;

async function handleRequest(request: Request, env: Env): Promise<Response> {
  const url = new URL(request.url);

  if (url.pathname === '/health') return Response.json({ ok: true });

  if (url.pathname.startsWith('/api/')) {
    return Response.json({ route: url.pathname });
  }

  return new Response('Not found', { status: 404 });
}
```

## Implementation Details

- **`ws: true`** in `http-proxy-middleware` enables WebSocket proxying for Vite HMR. The standalone server additionally needs to forward the raw `upgrade` event from the HTTP server to the proxy instance.
- **`changeOrigin: true`** rewrites the `Host` header on the proxied request to match the target server. Without it, the Worker may reject requests with a `Host` mismatch.
- **`X-Dev-Proxy` header** is a convention that tells the Worker it is being called from the local dev proxy. The Worker can use this to:
  - Relax CSP headers.
  - Add CORS `Access-Control-Allow-Origin`.
  - Return more verbose error bodies.
  - Skip rate limiting.
- **Vite `define`** injects string constants at build time. The frontend never needs to `fetch('/api')` with a hardcoded port — it always uses a relative URL that the proxy intercepts.
- **mkcert certificates** are trusted by the OS and therefore by Chrome/Firefox without security warnings. Node.js does not read the OS trust store by default — set `NODE_EXTRA_CA_CERTS` to the mkcert root CA.

---

## Anti-patterns

- **Using `Access-Control-Allow-Origin: *` in production** — the `X-Dev-Proxy` guard keeps this local-only. Never merge wildcard CORS into your production Worker path.
- **Committing `localhost.pem` / `localhost-key.pem`** — these are secret keys. Add `dev-proxy/*.pem` to `.gitignore`.
- **Hardcoding `127.0.0.1:8787` in frontend code** — use the `define`/`env` pattern so the origin is configurable without a code change.
- **Running the proxy on the same port as Vite** — this requires stopping Vite and starting the proxy instead. Running them on separate ports (proxy: 4000, Vite: 5173) is less error-prone.

---

## Gotchas

- `wrangler dev` binds to `127.0.0.1` by default. If the proxy runs in Docker or a remote dev environment, change to `--ip 0.0.0.0` in the `dev:worker` script and update `WORKER_ORIGIN` accordingly.
- Vite's built-in proxy does **not** forward WebSocket connections for all versions. Use the standalone `http-proxy-middleware` server if HMR breaks.
- `http-proxy-middleware` v3 changed the `onProxyReq` hook to the `on: { proxyReq }` signature. The v2 API (`onProxyReq` at top level) is deprecated — do not copy old Stack Overflow examples.
- Cookie `SameSite=None; Secure` requires HTTPS. For local HTTPS, the `USE_HTTPS=true` flow with mkcert is the only reliable path — `localhost` is treated as a secure context by Chrome regardless, but Safari requires HTTPS for `Secure` cookies even on localhost.

## Verification

```bash
# Start all three processes
npm run dev

# Confirm Worker route is proxied
curl -s http://localhost:4000/health | jq .
# Expected: {"ok":true}

# Confirm Vite route is proxied (should return HTML)
curl -si http://localhost:4000/ | head -5
# Expected: HTTP/1.1 200 OK with text/html content-type

# Confirm HMR WebSocket is forwarded
# (check browser DevTools → Network → WS tab for a 101 Switching Protocols)

# HTTPS variant
USE_HTTPS=true npm run dev:proxy &
curl -s https://localhost:4000/health  # should not error on cert
```
