# message-deduplication

**Issue:** Preventing duplicate message processing in distributed messaging systems
**Date:** 2026-08-11
**Status:** documented

## Symptom / Context
Broker retries, consumer restarts, and network issues all lead to the same message being delivered multiple times.

## Pattern / Solution
Deduplication can happen at the broker level or consumer level.

Broker-level (SQS):
```
SQS FIFO: MessageDeduplicationId on send
  - Same ID within 5-minute deduplication window = dropped
  - ContentBasedDeduplication: SHA-256 of body as ID
```

Consumer-level (DB):
```python
def handle(message):
    msg_id = message.attributes['MessageId']
    if db.exists("SELECT 1 FROM processed_messages WHERE id = %s", msg_id):
        return  # already processed
    with db.transaction():
        db.execute("INSERT INTO processed_messages (id) VALUES (%s)", msg_id)
        process_business_logic(message.body)
```

Bloom filter for high-throughput deduplication (probabilistic, no false negatives if tuned correctly).

## Gotchas
- Deduplication window must exceed maximum retry/redelivery window
- Message IDs must be stable across retries — generated by producer, not broker
- Bloom filter false positives drop legitimate messages; size appropriately
