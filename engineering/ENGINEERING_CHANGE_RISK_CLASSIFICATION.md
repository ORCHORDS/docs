# Engineering Change Risk Classification

## Purpose

Apply proportionate review and evidence to changes based on potential consequence rather than file count or author seniority.

## Factors

Change risk SHOULD consider blast radius, reversibility, data mutation, privilege, authentication/authorization impact, dependency change, migration complexity, user harm, operational coupling, and novelty.

Higher-risk changes warrant stronger review, testing, rollout safeguards, observability, and rollback evidence.

Low-risk classification should be explainable and should not be used to bypass controls for urgent work.
