# error-codes-and-responses

**Issue:** Consistent error response format across all API endpoints
**Date:** 2026-08-11
**Status:** documented

## Standard error shape

Every error response must be JSON with this shape:

```json
{
  "error": "snake_case_code",
  "message": "Human-readable description (optional)",
  "request_id": "uuid-or-cf-ray"
}
```

Generated by `jsonError` from `_lib/auth.ts`:

```typescript
export function jsonError(
  status: number,
  code: string,
  message?: string,
  request_id?: string,
): Response {
  return new Response(
    JSON.stringify({ error: code, message, request_id }),
    { status, headers: { 'content-type': 'application/json' } },
  );
}
```

## Standard status codes

| Status | Code | Situation |
|--------|------|-----------|
| 400 | `invalid_request` | Missing required field, bad format |
| 400 | `invalid_json` | Request body is not valid JSON |
| 400 | `no_updates` | PATCH body has no recognized fields |
| 401 | `unauthorized` | No session or token; re-auth required |
| 403 | `forbidden` | Authenticated but insufficient role |
| 404 | `not_found` | Resource doesn't exist (or is soft-deleted) |
| 409 | `conflict` | Duplicate — unique constraint would be violated |
| 422 | `validation_error` | Semantically invalid (e.g. invalid enum value) |
| 429 | `rate_limited` | Too many requests |
| 500 | `internal_error` | Unexpected server error — don't leak details |
| 503 | `database_unavailable` | DB binding missing or D1 unavailable |

## jsonError usage rules

```typescript
// 401 — no ctx yet, so request_id is undefined:
if (!ctx) return jsonError(401, 'unauthorized', undefined, undefined);

// 403 — ctx is available:
if (!roleAtLeast(ctx.user.role, 'admin')) {
  return jsonError(403, 'forbidden', 'Admin role required', ctx.request_id);
}

// 404 — hide whether resource exists in other tenants:
return jsonError(404, 'not_found', 'Control not found', ctx.request_id);

// 400 — include actionable message:
return jsonError(400, 'invalid_request', 'name is required and must be non-empty', ctx.request_id);

// 500 — never return internal error details to clients:
console.error('Unexpected error:', e);
return jsonError(500, 'internal_error', undefined, ctx?.request_id);
```

## Never do this

```typescript
// Wrong — leaks stack trace or internal message to client:
return new Response(e.message, { status: 500 });

// Wrong — wrong content-type:
return new Response('Not found', { status: 404 });

// Wrong — non-standard shape:
return new Response(JSON.stringify({ status: 'error', reason: 'bad' }), { status: 400 });

// Wrong — 403 when resource might belong to another tenant (leaks existence):
if (row.tenant_id !== ctx.tenant.id) return jsonError(403, 'forbidden', ...);
// Correct:
if (!row || row.tenant_id !== ctx.tenant.id) return jsonError(404, 'not_found', ...);
```

## Success shapes

```typescript
// 200 OK — list response:
return jsonOk({ controls: rows.results, count: rows.results.length }, ctx.request_id);

// 200 OK — single resource:
return jsonOk({ control: row }, ctx.request_id);

// 201 Created — after INSERT:
return jsonCreated({ id, name });  // no request_id arg

// 204 No Content — after DELETE or action with no body:
return new Response(null, { status: 204 });
```

## SCIM error shape (different format)

SCIM 2.0 errors use a different schema — don't use `jsonError` for SCIM endpoints:

```typescript
function scimError(status: number, scimType: string, detail: string): Response {
  return new Response(JSON.stringify({
    schemas: ['urn:ietf:params:scim:api:messages:2.0:Error'],
    status: String(status),
    scimType,
    detail,
  }), {
    status,
    headers: { 'content-type': 'application/scim+json' },
  });
}
```

## Validation errors — include field name

When a field fails validation, include the field name in the message:

```typescript
if (!body.name?.trim()) {
  return jsonError(400, 'invalid_request', 'name: required, must be non-empty', ctx.request_id);
}
if (body.name.length > 255) {
  return jsonError(400, 'invalid_request', 'name: max 255 characters', ctx.request_id);
}
if (!VALID_STATUSES.includes(body.status)) {
  return jsonError(422, 'validation_error',
    `status: must be one of ${VALID_STATUSES.join(', ')}`, ctx.request_id);
}
```

## try/catch — always return 500 not throw

```typescript
try {
  const rows = await env.DB!.prepare(...).all();
  return jsonOk({ results: rows.results }, ctx.request_id);
} catch (e) {
  console.error('[handler] db error:', e);
  return jsonError(500, 'internal_error', undefined, ctx.request_id);
}
```

Workers catch unhandled rejections and return a default 500, but logging is lost.
Always catch and log explicitly.
