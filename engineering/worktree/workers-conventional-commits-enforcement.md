# Conventional Commits Enforcement for Cloudflare Workers Repos

Date: 2026-08-24
Author: example.com
Status: production

---

## Symptom / Use-case

Teams working on Cloudflare Workers monorepos or multi-package repos accumulate commit history that is impossible to parse. Automated CHANGELOG generation fails, semantic versioning cannot be derived automatically, and PR reviewers spend time deciphering intent from vague messages like `fix stuff` or `wip`. You need a structured, machine-readable commit convention enforced at every layer: local hook, CI gate, and release pipeline.

## Context

Conventional Commits (https://www.conventionalcommits.org) specifies a lightweight message structure:

```
<type>(<scope>): <short description>

[optional body]

[optional footers]
```

For Workers repositories the **scope** should map to a deployable unit — a Worker name, a Durable Object package, or a shared library. Enforcement happens at three points:

1. `commit-msg` git hook (developer machine, instant feedback)
2. `commitlint` in CI (PR gate, catches squash-merge renames)
3. `release-please` or `conventional-changelog` in the release pipeline (CHANGELOG + version bump)

## Solution

### 1. Define allowed types and scopes

Create `commitlint.config.ts` at repo root:

```typescript
// commitlint.config.ts
import type { UserConfig } from '@commitlint/types';

// Derive scope list from your Workers package directories at lint time
import { readdirSync } from 'fs';
import { join } from 'path';

function getWorkerScopes(): string[] {
  const workersDir = join(__dirname, 'workers');
  try {
    return readdirSync(workersDir, { withFileTypes: true })
      .filter((d) => d.isDirectory())
      .map((d) => d.name);
  } catch {
    return [];
  }
}

const ALLOWED_TYPES = [
  'feat',     // new feature visible to consumers
  'fix',      // bug fix
  'chore',    // maintenance, dep updates
  'docs',     // documentation only
  'test',     // adding or fixing tests
  'refactor', // code restructure without behaviour change
  'perf',     // performance improvement
  'ci',       // CI/CD pipeline changes
  'revert',   // reverts a prior commit
];

const workerScopes = getWorkerScopes();
const SHARED_SCOPES = ['shared-types', 'config', 'infra', 'release'];
const ALL_SCOPES = [...workerScopes, ...SHARED_SCOPES];

const config: UserConfig = {
  extends: ['@commitlint/config-conventional'],
  rules: {
    'type-enum': [2, 'always', ALLOWED_TYPES],
    'type-case': [2, 'always', 'lower-case'],
    'scope-enum': [2, 'always', ALL_SCOPES],
    'scope-case': [2, 'always', 'kebab-case'],
    'subject-case': [2, 'never', ['sentence-case', 'start-case', 'pascal-case', 'upper-case']],
    'subject-empty': [2, 'never'],
    'subject-full-stop': [2, 'never', '.'],
    'header-max-length': [2, 'always', 100],
    'body-leading-blank': [1, 'always'],
    'footer-leading-blank': [1, 'always'],
  },
};

export default config;
```

### 2. commit-msg hook (local enforcement)

Install via `simple-git-hooks` or `husky`. This example uses `simple-git-hooks` for zero-runtime-overhead:

```bash
# package.json (root)
{
  "devDependencies": {
    "@commitlint/cli": "^19.0.0",
    "@commitlint/config-conventional": "^19.0.0",
    "@commitlint/types": "^19.0.0",
    "simple-git-hooks": "^2.11.0"
  },
  "simple-git-hooks": {
    "commit-msg": "npx --no -- commitlint --edit $1"
  },
  "scripts": {
    "prepare": "simple-git-hooks"
  }
}
```

Run once after install:

```bash
npm install
npx simple-git-hooks   # writes .git/hooks/commit-msg
```

The hook file written to `.git/hooks/commit-msg`:

```bash
#!/bin/sh
# Auto-generated by simple-git-hooks
npx --no -- commitlint --edit "$1"
```

### 3. Raw regex hook (zero-dependency fallback)

For environments where Node is unavailable at hook time:

```bash
#!/bin/sh
# .git/hooks/commit-msg

MSG_FILE="$1"
MSG=$(cat "$MSG_FILE")

# Strip comments
MSG=$(echo "$MSG" | sed '/^#/d')

CONVENTIONAL_PATTERN='^(feat|fix|chore|docs|test|refactor|perf|ci|revert)(\([a-z0-9-]+\))?(!)?: .{1,100}$'

FIRST_LINE=$(echo "$MSG" | head -1)

if ! echo "$FIRST_LINE" | grep -qE "$CONVENTIONAL_PATTERN"; then
  echo ""
  echo "ERROR: commit message does not follow Conventional Commits format."
  echo ""
  echo "Expected: <type>(<scope>): <description>"
  echo "Example:  feat(api-gateway): add rate limiting header"
  echo ""
  echo "Allowed types: feat fix chore docs test refactor perf ci revert"
  echo "Your message: $FIRST_LINE"
  echo ""
  exit 1
fi

exit 0
```

### 4. CI enforcement (GitHub Actions)

```yaml
# .github/workflows/commitlint.yml
name: Commitlint

on:
  pull_request:
    types: [opened, synchronize, reopened, edited]

jobs:
  commitlint:
    name: Lint commit messages
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
        with:
          fetch-depth: 0  # need full history to compare branches

      - uses: actions/setup-node@v4
        with:
          node-version: '22'
          cache: 'npm'

      - name: Install dependencies
        run: npm ci --ignore-scripts

      - name: Validate PR commit messages
        run: |
          npx commitlint \
            --from ${{ github.event.pull_request.base.sha }} \
            --to ${{ github.event.pull_request.head.sha }} \
            --verbose

      - name: Validate PR title (for squash merges)
        env:
          PR_TITLE: ${{ github.event.pull_request.title }}
        run: echo "$PR_TITLE" | npx commitlint
```

### 5. Automated CHANGELOG with `conventional-changelog`

```typescript
// scripts/generate-changelog.ts
import { execSync } from 'child_process';
import { writeFileSync, readFileSync, existsSync } from 'fs';

const CHANGELOG_FILE = 'CHANGELOG.md';
const PACKAGE_JSON = JSON.parse(readFileSync('package.json', 'utf-8'));

function getLastTag(): string {
  try {
    return execSync('git describe --tags --abbrev=0', { encoding: 'utf-8' }).trim();
  } catch {
    // No tags yet — use first commit
    return execSync('git rev-list --max-parents=0 HEAD', { encoding: 'utf-8' }).trim();
  }
}

function generateChangelog(): void {
  const lastTag = getLastTag();
  const nextVersion = process.env.NEXT_VERSION ?? PACKAGE_JSON.version;

  console.log(`Generating CHANGELOG from ${lastTag} to HEAD for v${nextVersion}`);

  execSync(
    `npx conventional-changelog-cli \
      -p conventionalcommits \
      -i ${CHANGELOG_FILE} \
      -s \
      -r 0`,
    { stdio: 'inherit' }
  );

  console.log(`CHANGELOG updated: ${CHANGELOG_FILE}`);
}

generateChangelog();
```

Add to `package.json` scripts:

```json
{
  "scripts": {
    "changelog": "tsx scripts/generate-changelog.ts",
    "release": "npm run changelog && git add CHANGELOG.md && git commit -m 'chore(release): update CHANGELOG'"
  }
}
```

## Implementation Details

- `scope-enum` is derived at lint config load time from the filesystem, so adding a new Worker directory automatically makes its name a valid scope — no manual config update needed.
- The `!` (breaking change) suffix in the regex pattern (`(!)?: `) allows `feat(api-gateway)!: drop v1 endpoint` to pass validation while being flagged for MAJOR version bump.
- `--edit $1` in the hook tells commitlint to read from the temp file git provides, not stdin, so multi-line messages work correctly.
- For monorepos using Turborepo or Nx, scope validation can be driven from `turbo.json` pipeline keys instead of directory scanning.
- The CI job validates both individual commits (`--from`/`--to`) and the PR title. This covers both rebase-merge (each commit) and squash-merge (title becomes the single commit message) strategies.

## Anti-patterns

- **Skipping scope entirely**: `feat: add retry logic` is technically valid per spec but useless in a multi-Worker repo — enforce scope as required.
- **Using `wip` as a type**: tempting for developers, but it trains the team to bypass the convention; disallow it explicitly in `type-enum`.
- **Only enforcing locally**: hooks can be bypassed with `git commit --no-verify`; CI enforcement is the authoritative gate.
- **Static scope list in config**: manually maintained scope lists drift from reality; derive from the filesystem or package manifest.
- **Validating only the latest commit in CI**: `--from`/`--to` must span all commits in the PR, not just HEAD.

## Gotchas

- `simple-git-hooks` requires `npm run prepare` to be re-run after each `npm install` on a fresh clone, because it writes hooks into `.git/` which is not tracked. Add a `postinstall` script or document in onboarding.
- `fetch-depth: 0` in the Actions checkout is mandatory; shallow clones (the default) omit the base SHA and cause `git log` to fail.
- If the repo uses merge commits from dependabot, add a `ignoredAuthors` or path filter to skip bot commits in CHANGELOG generation.
- `commitlint.config.ts` requires `ts-node` or `tsx` in `devDependencies`; alternatively use `.cjs` format to avoid the TypeScript toolchain at hook time.

## Verification

```bash
# Test a valid commit message
echo "feat(api-gateway): add rate limiting" | npx commitlint
# exit 0

# Test an invalid message
echo "WIP: fixing stuff" | npx commitlint
# exit 1 with error output

# Test the hook is installed
cat .git/hooks/commit-msg

# Dry-run changelog generation
npx conventional-changelog-cli -p conventionalcommits -r 1
```
