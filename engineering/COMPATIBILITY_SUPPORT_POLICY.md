# Compatibility and Support Policy

## Purpose

Define how supported interfaces, formats, runtimes, and versions evolve without accidental permanent compatibility promises.

## Requirements

Material compatibility commitments SHOULD identify supported scope, deprecation approach, migration expectations, notice where appropriate, and conditions for breaking change.

Undocumented behavior should not automatically become a permanent public contract merely because it once worked.

Compatibility decisions should balance user impact, security, maintainability, and operational cost.
